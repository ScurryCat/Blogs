## 2. 架构：两层数据，自动保存绝不碰正式内容

设计书 §3.1 的硬约束：**自动保存禁止直接调用正式内容更新接口**（对已发布内容可能在用户
点击发布前就改变访客看到的内容）。因此：

```
浏览器编辑器（INS / 手记）
   ├─ 每次输入（1s 防抖 / 持续输入最长 5s）
   │     → 本机恢复副本 localStorage（按站主隔离，未登录不读写）
   │     → PATCH /api/v1/admin/work-drafts/{id}（串行队列 + 草稿版本 If-Match）
   └─ 用户显式点「保存 / 发布 / 更新正式内容」
         → POST /api/v1/admin/work-drafts/{id}/commit（单事务 + 双版本检查 + 幂等）
               → 正式内容 moments / journal_entries（+ 媒体关系 + 相册来源 + 发布状态）
```

- 工作草稿是**独立表**（`work_drafts` / `work_draft_media`），不是新的公开内容类型：
  公开列表、搜索、图库、访客接口都读不到；草稿的媒体保留关系**不授予**匿名访问。
- commit 在**同一个数据库事务**内完成：正式内容行 + 媒体关系 + 动态→相册收录来源
  （复用 `gallery.sources` 的 validate/replace/prune）+ 发布状态 + 草稿 `committed_*`，
  失败整体回滚（草稿保持 active、正式内容不变）。
- 并发：`SELECT ... FOR UPDATE` 锁草稿行 / 正式内容行；PATCH 用草稿版本 If-Match（428/412）。
- 幂等：`commit_key`（uuid）为必填；**幂等回放优先于 If-Match**（网络重试携带旧 If-Match 是常态，
  同 key 直接返回上次结果 `idempotent_replay:true`）；不同 key 二次提交 409；
  `(owner_id, commit_key)` 部分唯一索引兜底跨草稿复用（409）；重复提交不产生重复内容/收录关系。
- 手记语义：`save` = 正式草稿（draft + private），`publish` = 独立的公开动作（复用既有发布门槛），
  `update` = 已公开手记的「更新正式内容」；修改公开内容期间访客继续看到原版本。

## 3. 后端接口速查（全部在 `/api/v1` 下）

### 3.1 工作草稿 `/admin/work-drafts`（站主；写操作要 Origin + CSRF）

| 方法 | 路径 | 关键语义 |
|---|---|---|
| POST | `/admin/work-drafts` | 创建或恢复。已有 target 且存在 active 草稿 → **200** `{draft,reused:true}`（请求 data/images 不覆盖既有）；否则 **201**。`target_id` 不存在/已删除/非本人 → 404。target_version 由服务端写 |
| GET | `/admin/work-drafts?content_type=&cursor=&limit=` | 仅本人 **active**；`updated_at DESC,id DESC`；`{items,next_cursor}`；limit 默认 12 / 最大 30（超 422） |
| GET | `/admin/work-drafts/{id}` | 详情（带 `ETag: "<draft_version>"`；非本人/不存在 404） |
| PATCH | `/admin/work-drafts/{id}` | 保存工作副本。`If-Match: "<draft_version>"`（缺失 428 / 不符 412）；`data` 浅合并（未知键 422）；`images` 省略=不动、给出=整组替换；成功 `draft_version+1`；非 active 409 |
| POST | `/admin/work-drafts/{id}/commit` | 显式提交。body `{action:"save"\|"publish"\|"update", expected_target_version, commit_key}`；If-Match 草稿版本；双版本检查；幂等；单事务 |
| DELETE | `/admin/work-drafts/{id}` | 丢弃：active→discarded（204），删 `work_draft_media` 行、**不删媒体文件**，不影响正式内容/其他引用；已提交/已丢弃 409 |

关键 DTO（wire 为 snake_case）：

```jsonc
// WorkDraftOut（POST 包在 {draft, reused} 里；GET 详情/PATCH 直接返回）
{
  "id": "uuid", "content_type": "moment|journal",
  "target_id": "uuid|null", "target_version": 1,
  "draft_version": 1, "status": "active",
  "summary": "列表用一行摘要（服务端派生）",
  "data": { /* moment: text,tags,album_links；journal: entry_date,title,content_md,mood,location,post_id */ },
  "images": [{"media_id":"uuid","position":0,"alt":"","media":{/* MediaAdminOut */}}],
  "created_at": "ISO8601", "updated_at": "ISO8601"
}

// CommitResultOut
{ "draft_id":"uuid","content_type":"moment|journal","target_id":"uuid",
  "target_version":4,"status":"draft|published","visibility":"private|public|null",
  "action":"save|publish|update","idempotent_replay":false }
```

动作矩阵（服务端强制）：moment 无 target→`save`/`publish`；target draft→`save`/`publish`；
target published→`update`（`publish` 无意义→409）。journal 无 target→`save`/`publish`；
target draft→`save`/`publish`；target published→`update`（只能「更新正式内容」）。
`expected_target_version`：已有 target 必填且与正式内容当前版本一致（缺失 422 / 不一致 412）；
新内容必须为 null。

错误码沿用全局格式 `{error:{code,message,fields},request_id}`：401 未登录、404 非本人/不存在、
409 状态冲突、412 `VERSION_CONFLICT`、428 `PRECONDITION_REQUIRED`、422 `VALIDATION_FAILED`（字段级）。
commit 时正式内容发布校验失败统一 **422**（与既有管理接口的 409 风格不同，是本批刻意的契约选择）。

## 10. 坑与约定（接手先看）

- **只本地提交、不自动推送**（项目约定）；提交消息用中文 conventional 风格。
- `verify-all.sh --fast` **不等于** CI：它不跑 backend / build / `gen:api` 漂移；大改动要另跑。
- 隔离栈 `e2e-stack.sh up` 每次会重建库；源码比构建新时要 `rm -rf /tmp/pl-e2e-stack/web` 强制重建，
  否则会跑旧 bundle。`down` 必须带显式 PGDATA/端口，别误停共享 55432。
- Python 脚本要 `no_proxy`（macOS Python 3.13 会走系统代理）；UV 要 `UV_CACHE_DIR`；
  PG 要 `LC_ALL=C`；Next 在沙箱内要 `HOME=/tmp/...`（写 `~/Library/Preferences` 会被 EPERM，
  与代码无关）。
- 登录限流 5/min；e2e 复用同一 cookie。CSRF 走 `X-CSRF-Token` 头（JSON body 的 csrf 只在 ≤4096 字节时
  生效——长手记正文必须用头）。写操作要 Origin。
- 公开页面 owner 入口只做条件渲染，**隐藏入口不是授权**；管理接口一律由后端
  `require_admin*` 校验。媒体对匿名可见的条件仍是「ready + 未删除 + 至少一个公开引用」，
  草稿保留关系不贡献公开引用。
- `data-*` 选择器是 e2e 契约（§4.3），改名/删除要先查 `tools/e2e-p5-workspace.py` 与验收报告。
- 自动化脚本、formatter、代码生成器不受文件版本守卫保护：`.next`、`tsconfig.tsbuildinfo`、
  `lib/api/generated/schema.ts` 由命令生成，别手改生成文件。
