## 1. 方法：`tools/audit-failure-states.py`（新增，可复用）

- 起一个**接口指向死端口**的 dev 实例（`API_INTERNAL_URL/DEV_API_URL=http://127.0.0.1:9`），
  站点其余部分照常渲染 → 模拟「API 完全不可用」；
- 逐页检查：可见失败原因文案、重试入口、是否被 Next 错误覆盖层占据、页面 JS 错误；
- 将页面分成两类断言：
  - **依赖 API 的 11 页**（home/about/showcase/gallery×2/velvet/metanav/coop/leisure/journal/mementos）：
    必须出现失败原因，不能静默降级；
  - **不依赖 API 的 4 页**（posts、文章详情、guestbook：本机存储示例、weather：外部气象接口）：
    不要求失败态，但不许崩溃/错误覆盖层；
- `--json` 落盘；有页面静默降级时退出码 1。

## 3. 发现并修复：两处长尾「失败态无重试」

天鹅绒房间与印象空间的**首屏读取失败**只有一行 `role="alert"` 文案，**没有重试入口**
（此前只有分页「读取更多」失败场景的重试）；用户只能整页刷新。

修复：
- `features/velvet/velvet-view.tsx`、`features/exploration/mementos-view.tsx`：
  失败态增加「重新读取」按钮 → 原地重新请求首屏（带当前 domain / work_status），
  成功后恢复列表，失败则刷新失败文案；请求仍走既有 `inflight` 取消约定；
- 两处 CSS 补按钮间距；新增 2 条单测断言「点击后重新请求首屏并恢复列表」；
- 浏览器实测（死 API 实例）：点击后从 SSR 失败文案切换为客户端失败文案，按钮可再次点击 → 恢复路径闭环。
