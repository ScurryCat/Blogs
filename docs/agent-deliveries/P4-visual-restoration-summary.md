## 1. 方法（为什么这样还原）

1. **先审计参考库，再动手**：把本地离线参考库（P5 官方画册 259 页 200dpi、P5/P5R HUD sprite 表 30 张、
   图片/视频目录）逐页/逐张过一遍，确认每个界面**到底有没有整屏参考帧**。结论：
   **IM 有唯一一张完整屏**；其余界面只有**元件表**（按钮、标签、卡片、图标），没有整屏帧。
2. **按参考级别决定还原口径**：
   - 有整屏帧 → 可以按布局语言还原（IM）；
   - 只有元件表 → 只做**元件/构图语言级还原 v1**，并明确标注「整屏还原未完成」，不拿近似素材冒充；
   - 完全没有参考 → 只做站内一致性整理，不宣称还原。
3. **每条交付都带真实浏览器证据**：隔离 e2e 全栈（独立 PG 集群 + API + 前端构建）+ 种子数据 +
   Playwright 截图与计算样式断言；截图放工作区外 `.dsh/`，报告写进 `docs/agent-deliveries/`。
4. **尽量把「视觉改动」与「真实缺陷」分开记录**：视觉是 v1；缺陷是必须修复项（见 §4）。

## 4. 顺手修复的真实缺陷（都在上面矩阵里有交付单记录）

1. **手机内 IM 完全没有样式**（`messaging.css` 只被独立路由 import）→ 根布局统一 import。
2. **独立应用页 / 顶层页 / 子路由页被 fixed HUD 压住**（共 3 批）→ 统一 `AppPageShell`；
   现在 `app/` 下已无裸 `section.shell`（grep 为空），`.app-page` 实测 `padding-top: 96px`。
3. **放课后 / 异世界导航整套样式按浅色主题写死** → 改深色站点主题。
4. **生活图库灯箱 dev 模式打不开**（StrictMode 清理触发 `restoreFocus`，回调里顺手关灯箱）→ 拆开关闭与焦点归还。
5. **灯箱顶栏被 HUD 盖住**（`z-index: 80 < 950`）→ `z-index: 960`。
6. **手记手机页签重复「日历」**（reading 详情屏被当页签渲染）→ 只列浏览两屏。
7. **手机桌面裂图**（新增应用没有 `app/<id>.png`）+ **两个内置应用从未登记**（天鹅绒/印象空间）→ 补图标 + 补登记 + 回归测试。
8. 若干对比度/可读性修复（管理端输入框白底浅字、浅色卡片等）。
