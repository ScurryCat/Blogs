## 1. 覆盖流程（真实浏览器 UI，非接口直调）

`tools/e2e-ins-draft-album-flow.py`，**19/19 通过**：

1. owner 登录（隔离栈站主）；
2. 新建动态草稿：上传图片 + 替代文本 + 正文，**暂不保存**；
3. 点「新建相册（新标签页）」→ 弹出页创建相册**草稿**（当前动态表单不动）；
4. 回到动态页断言：正文 / 替代文本 / 图片上传状态**全部保留**；
5. 刷新相册列表 → 选中新相册（草稿）→ 添加并勾选图片 → 保存草稿（收录关系落库）；
6. 在新标签页把相册**发布**（此时相册已有该图关系）；
7. 发布动态；
8. `/apps/ins` 公开页出现该动态；
9. `/gallery?scope=album&album=<slug>` 出现该图（alt/说明可见，媒体请求 HTTP 200）；
10. 管理端重新打开该动态 → **撤回**；
11. 撤回后：公开 INS 不再出现该动态；图库相册页不再显示该图 alt（公开来源撤回联动）。

## 2. 与旧 9/9 流程的差别

| 旧流程 | 新流程 |
| --- | --- |
| 先建相册草稿 → 再建动态 → 收录 → 发布动态 | 先编辑动态草稿 → **新标签建相册** → 断回草稿保留 → 收录 → 发布相册 → 发布动态 |
| 只断言公开 INS 可见 | 加断言：**图库相册页可见 + 图片 200**；**撤回后 INS/图库都消失** |
| 在共享演示库运行 | **隔离栈**（独立集群/API/前端），不碰共享数据 |

## 4. 说明与边界

- 隔离栈的相册发布需要「至少一张照片」：因此顺序改为「先保存收录关系 → 发布相册 → 发布动态」，
  与产品实际限制一致，不是放宽校验；
- 图库撤回联动验证的是「动态来源不再贡献公开资格」；相册本身仍保持已发布（照片关系保留），
  与 N3 契约「撤回只撤公开资格、配置保留」一致；
- 本证据覆盖 §7.4 的管理端流程缺口；**不改变** G2 参考帧缺失、真机验证、剩余原作图标等未关闭项。
