## 2. 本轮发现的真实整合缺口（已修）

**T02 套件与第三轮导航改版不一致**：第三轮把顶部导航从
「文章 / 地图 / 天气 / 留言板 / 关于」改成「文章 / 生活 / 作品 / 地图 / 关于」——
**天气与留言板不再在导航里**（`/weather`、`/guestbook` 路由仍 200，直接访问无影响）。
T02 有一条用例点 `.hud-nav a[data-k="weather"]`，等不到元素直接超时，**整份套件跑不完**。

- 该用例语义是「从地图页点顶部导航必须用 Joker 帷幕，不能因在地图页就播人群」，
  **目标页只是附带条件**；
- 改为点中性的「文章」入口（`posts`）、断言目的地 `/posts`，**语义不变**；
- 套件里其它导航引用已核对：`data-k="about"` 仍存在；`/weather`、`/guestbook` 作为
  直接 URL 截图用例保留（路由仍 200）。

## 3. 环境竞态（不是代码缺陷，但会污染验收）

本轮 T02 曾两次失败，症状是 `500 /_next/static/chunks/*.js` 与
`window.__PHANTOM_DEBUG__ is not a function`。排查结论：**并行 worker 同时在重建同一个
`.next`**，导致页面 HTML 引用的 chunk 哈希与磁盘上的构建产物不匹配（HTML 是旧构建、
chunk 已被新构建替换）。「重建 → 重启 → 立即跑」后即 52/52。

> 这与第 8 轮的后端撞库是同一类问题：**共享工作区里，构建产物与测试数据库都是共享状态**，
> 任何一方的并发操作都会让另一方的验收数据失真。
> **建议**：验收阶段应由一方独占执行，或给两方各自独立的 `.next` 与测试库前缀。
