## 6.5 本轮新增观察（不是缺陷结论，需 P4/Lead 决策）

### O1 手机里点 INS 的标签 chip 会**跳出手机**

`features/ins/feed-view.tsx` 的标签 chip 用的是 `next/link` 的裸 `<Link>`，
而项目约定（T02 写在 `messaging/content-card.tsx` 顶部）是**一律用 `SiteLink`**：
裸链接 / 自己写 onClick 会让部分跳转退化。后果：在手机里点标签会导航到
`/apps/ins?tag=…`，**手机随之关闭**，落到独立页。

- 手机里磁贴走的是 `host.openSiteContent({source:"phone-link"})`，两者不一致；
- 但手机 URL 状态只有 `phone / screen / item`，**表达不了 tag**，
  所以「在手机内过滤」需要扩展手机 URL 契约 —— 属产品/契约决策，本轮不动（P4/INS 在并行改动中）。

### O2 手机里的 IM 可能出现**嵌套滚动**

`.msg-list` 自带 `max-height: min(56vh, 520px)` 并在内部滚动，而手机屏幕本身也是滚动区
（`.pw-screen`）。IM 内容高度超过屏幕时，会出现「列表滚 + 屏幕滚」两个容器，
与既有的「同一区域只留一个主手势」设计原则相悖。属视觉/交互精修，需图像能力核对后再动。

## 6.6 第 18 轮补充：隔离构建验证（解决「共享 .next 无法验证 HEAD」）

新增 **`tools/verify-isolated.sh [端口]`**：把源码复制到 `/tmp`、**硬链接** `node_modules`、
在隔离副本里 patch `turbopack.root`、用 **Turbopack** 构建、起服务后跑 T02 + 取数审计。
**不碰仓库的 `.next`** —— 并行 worker 在跑的共享构建不会被打断。

实测（对当前 HEAD）：T02 **52/52** ✓、取数审计 **0 失败** ✓，退出码 0。

两条踩坑记录（已写进脚本注释，避免以后重复）：

1. **不能用 `--webpack` 构建去做验收**：T02 的 `.poll-q` 还原规则依赖 Turbopack/Lightning CSS
   会丢掉 `translate` 的行为；webpack 会**保留** `translate`，于是旧站的 `translate:-20px`
   与还原用的 `transform:translateY(-20px)` 叠加成 -40px，Q 装饰整体高 20px，
   T02 两条几何断言（与旧站 ≤2px）立刻失败。**这不是代码回归**，是构建工具差异。
   → 该还原规则本身是**构建工具相关**的脆弱点，若未来切换打包器需要重做这段。
2. **软链 `node_modules` 不行**：Turbopack 穿不过软链（报 `Could not find the Next.js package`），
   必须用**硬链接**（`cp -al`，同卷瞬时且是真实文件）。

## 6.7 第 19 轮补充：后端整树在独立集群上验证（942 / 0）

后端测试会在测试集群上建**固定名字**的库（`pl_test_*`），同一工作区两个 worker 同时跑就会
互相建/删同一个库，表现为 `database "pl_test_t01" does not exist` 与大批 ERROR —— 不是代码问题。

新增 **`tools/verify-backend-isolated.sh [端口]`**：在 `/tmp` 起第二个 Postgres 集群
（默认 55433）、建好 `pl_test`、跑后端整树、**跑完自动停并清理**，完全不碰共享集群。

实测（当前 HEAD）：**942 通过 / 0 失败**，退出码 0。

> 计数方式：该环境下 pytest 的总结行常被输出缓冲吞掉，脚本改用**进度点计数**作判据
> （全绿时每点 = 1 个通过），并同时记录 pytest 退出码 —— 两者一致才算通过。

### ⚠️ 本轮由我造成并已修复的一次环境事故（如实记录）

第 19 轮收尾时我执行了 `tools/pg-local.sh stop`，**第一条命令没带 `PGDATA` / `PL_PG_PORT`
覆盖** —— 于是它停掉的是**共享测试集群（55432）**，而不是我本想停的隔离集群。
后果：依赖 55432 的本地 API（8100）从那时起不可用，本轮首跑 4 个验收脚本时表现为
`会话端点返回 csrf_token 503`、登录 `403 CSRF 校验失败` 等连锁失败 —— **看起来像代码回归，
实际是环境被我停了**。

已用 `tools/pg-local.sh start`（默认参数）恢复共享集群，全部脚本随即通过。
教训：`pg-local.sh` 的默认目标是**共享集群**，停任何集群都必须显式带
`PGDATA=… PL_PG_PORT=…`；`verify-backend-isolated.sh` 的 trap 是在设置好这两个变量之后才
注册的，因此脚本本身是安全的 —— 出问题的是手工命令。

| 文件 | 处数 | 影响 |
| --- | --- | --- |

针对的是裸锚点），所以**功能上没有问题**；差别只是**跳过了全站过场动画**（`SiteLink` 走
导航协调器，才有 Joker 帷幕 / 手机内部短过渡）。属视觉一致性，非功能缺陷。

### O1 的正解方案（待决策，未实施）

「手机里点 INS 标签会跳出手机」的根因是**手机 URL 状态表达不了 tag**
（`?phone=<app>&screen=<s>&item=<i>`）。两条可选路：

1. **扩展手机 URL 契约**：给 `url-state.ts` 加 `tag`（或把筛选并入 `item` 的语义），
   让 `/apps/ins?tag=x` 在手机内等价于 `?phone=ins&tag=x`；
   代价：**修改路由约定**（§3.3 要求前进后退与直接链接含义一致），需同步 T02 套件与文档；
2. **接受现状**（点标签 = 离开手机去看独立页的筛选结果），把标签 chip 改成 `SiteLink`，
   至少让过场一致。

两条都未实施 —— 第 1 条动路由契约、第 2 条是纯视觉取舍，应由 Lead 定。

## 6.15 第 34 轮：浏览器端到端测量发现「手机滚动恢复」仍未生效（**未修完，如实记录**）

### 发现

用隔离全栈（独立集群 + 隔离 API + 15 条公开手记 + 真实浏览器）测「手记列表滚动 → 读取 → 返回」，
量出一个**此前单测发现不了**的事实：

> 手机里真正滚动的元素是 **`.pw-appbody`**（实测 scrollHeight 2608 / clientHeight 524，
> `overflow-y:auto`），**不是** `.pw-screen`。

而 `scrollContainerFor()` 第 14 轮只找 `.pw-screen` —— 所以**手机里的滚动记忆一直没生效**，
存的永远是 0。更糟的是 jsdom 单测自己也假设了 `.pw-screen`，**测试全绿但功能是坏的**。

### 已做

`scrollContainerFor()` 改为三级解析：**最近的可滚动祖先** → `.pw-screen` → window。
浏览器复测确认容器已能被正确找到（探针能滚到 1305px、列表 15 条都在）。

### 仍失败（未修完）

端到端**仍未通过**：进入正文时 `sessionStorage["journal.save.v1"]` 存的还是 **0**（应为 1305），
返回后自然恢复不了。已尝试两种取容器时机（effect 建立时 / 卸载时）都不行，
推测与「手机关闭时 DOM 先拆、可滚性量不出来」有关，需要更细的时序排查。

**因此本条不得计入「滚动恢复已完成」** —— 单测与接线测试通过，但**浏览器实测未通过**。
下一步应先在浏览器里定位「保存为何是 0」，再谈功能完成。
