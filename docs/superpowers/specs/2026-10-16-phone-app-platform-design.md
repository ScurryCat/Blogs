# 02 · 怪盗手机与可扩展应用平台

日期：2026-10-16

状态：待评审草案

入口：[设计总览](2026-10-16-next-phase-design.md)

## 1. 定位与现状

手机是随时可打开的“小型应用桌面”，不是装满跳转链接的第二个导航栏，也不是要求重做移动操作系统的模拟器。

当前 `phone.js` 同时生成外壳、播放器和六个固定入口。情报、地图、天气、档案实际是站点链接；音乐、音效是动作按钮。扩展前先分离三件事：手机宿主、持久站点服务、各应用视图。

首版目标：新增一个应用时，不必修改手机宿主或播放器；INS、异世界导航能在手机内使用，也能展开成独立页面。

## 2. 推荐的呈现方案

| 方案 | 体验 | 取舍 |
| --- | --- | --- |
| 保留透视手机外壳，所有应用都挤入原屏幕 | 游戏道具感强 | 复杂图文和表单被缩小，不适合长时间使用 |
| 所有应用直接跳独立页 | 最简单、最易读 | 手机只是链接菜单，缺少内置应用感 |
| 手机桌面保留道具感，应用使用直立阅读面板，并可展开独立页 | 保留仪式感，又能认真阅读 | 需要共用视图、返回栈和弹层管理；推荐 |

首版沿用第三种：桌面打开手机时保留现有外壳气质；进入内容应用，屏幕过渡成不做透视缩放的直立面板。小屏直接使用全屏应用面板，不显示缩小的手机 PNG。是否保留桌面整张外壳作为装饰，属于后续视觉评审，不改变应用接口。

## 3. 手机信息架构

```text
状态栏：时间 / 当前应用 / 收起
内容区：桌面或一个前台应用
  桌面：应用图标网格 + 简化的正在播放卡片
  应用：应用标题 / 返回 / 展开查看 / 应用内容
底部：回到桌面 / 迷你播放控制
```

- 桌面首批入口：INS、异世界导航、地图、天气、档案、音乐、设置。
- 原“情报”作为文章入口保留；图标多于一屏时正常滚动，不提前实现桌面拖拽、文件夹或复杂分页手势。
- 音效合并到设置，不为一个开关持续占用一个 App。
- 当前应用出错，只显示该应用的错误页，手机桌面、关闭和音乐仍可操作。
- 不放置假信号、假通知数量或无法使用的占位按钮；装饰状态需与真实信息明确区分。

新增内容完整后的桌面建议见 [07](2026-10-16-world-features-design.md)：INS、手记、放课后、COOP、异世界导航、音乐作为常用入口，现有入口保留在后续网格。这里的“首批”是宿主基础阶段，不要求新旧所有应用同时实现。INS 内包含动态 / 相册 / 角色消息，混合会话规则见 [08](2026-10-16-character-messaging-design.md)。

## 4. 应用注册表

注册表由仓库中的可信模块定义，首版不从数据库下载 JavaScript。

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定应用 ID，如 `ins`、`metanav`，不能随中文名称改变 |
| `name`、`subtitle`、`icon`、`order` | 桌面展示；图标使用已审核资源 |
| `kind` | `embedded` 为内置视图，`site-link` 为普通站点链接 |
| `canonical_path` | 独立页或站点目的地，用于展开、直接访问和无脚本回退 |
| `loader` | 仅内置应用拥有的构建期懒加载入口 |
| `feature_flag` | 编译配置决定是否启用，禁用时不能留一个坏图标 |
| `state_version` | 本机状态结构版本 |

宿主提供的服务仅包括：打开应用、内部换屏、返回、关闭、打开站内内容、提示消息、音频控制、版本化本机状态。应用不直接操纵全局 DOM、不自行锁 body、不新增全局音频，也不独立决定主站转场。

`feature_flag` 只控制可用性，不是鉴权。未来管理应用即便被手动打开，其 API 仍须验证站主会话。

## 5. 两种展示，共用同一功能

- `/apps/ins`、`/apps/ins/<id>`：独立信息流和动态详情。
- `/apps/metanav`、`/apps/metanav/palaces/<slug>`：独立导航和专题殿堂。
- 手机中的 INS / 异世界导航复用对应功能视图，宿主传入 `compact` 或 `expanded` 展示模式。
- 独立页提供真正的标题、描述、分享链接与首屏内容；不是一个空页面再自动弹出手机。
- 同时只挂载一份前台应用视图，避免独立页与隐藏手机重复取数据、产生两个相同的表单。
- “展开查看”关闭手机后进入 canonical 路由，恢复到同一条动态或殿堂，而不是返回应用首页。

首版无需使用 Next.js 并行路由、拦截路由或 iframe；如果未来需要更复杂的模态路由，再单独评估。

## 6. URL、返回与关闭

手机状态用站点 URL 的三个保留参数表达：

- `phone`：`home` 或已注册的内置应用 ID。
- `screen`：应用允许的屏幕枚举，例如 `feed`、`detail`、`palaces`、`palace`、`mementos`。
- `item`：详情 UUID 或殿堂 slug，由应用验证。

例如：`/posts/css-p5-menu?phone=ins&screen=detail&item=<uuid>`。保留原页面查询和 hash，不覆盖其他参数。分享按钮默认生成应用 canonical 链接，不暴露当前背景页面。

历史规则：

1. 点击手机图标，从无手机状态 push 一条 `phone=home` 记录。
2. 打开 App 和进入详情，继续 push 手机状态，禁止自动重复 push。
3. 浏览器 Back 与手机返回按钮遵循同一历史：详情 → 应用首页 → 桌面 → 原背景页。
4. 明确“收起手机”关闭整个手机，不逐层返回；宿主若持有本次打开的起点，回到该起点。
5. 直接访问带 `phone` 的链接，没有已知起点时，收起使用 replace 清除手机参数，不直接 `history.back()` 跳出本站。
6. 非法应用或 screen 回退到桌面，非法 item 显示应用内未找到；不会执行任意路径或外部 URL。
7. Back / Forward 只恢复状态，不重播主站过场、不改变背景页滚动位置。

URL 是“当前打开什么”的依据；局部筛选与滚动可以保存在 PhoneProvider。不要再维护一份与 URL 无关的平行返回栈。Query 参数变化本身不得触发页面过场或把手机重建。读取 URL 的客户端边界要遵循选定 Next.js 版本的预渲染要求，不把整站被动改为客户端渲染。

## 7. 生命周期与状态

前台应用遵循：未加载 → 加载中 → 前台 → 退出 / 卸载；异常进入应用错误页。返回桌面或收起手机后，不继续运行该应用的滚动监听、轮询、摄像头或动画。

| 状态 | 存放位置 | 退出后的行为 |
| --- | --- | --- |
| 当前 App / 详情 | URL | Back / Forward 可还原 |
| 列表滚动、筛选、已加载页 | 内存，按 App ID 分区 | 本次页面会话内恢复，设置容量上限 |
| 音量、曲目、音效 | 本机偏好 + AudioService | 换页、关手机不停止音乐 |
| INS 收藏、导航足迹 | 带版本的 localStorage | 跨刷新保留，仅本机；不上传 |
| 动态、殿堂、发布状态 | FastAPI / PostgreSQL | 服务端权威，不由本机状态覆盖 |
| 管理员会话 | HttpOnly Cookie + 服务端会话 | 不能放进 localStorage |

退出时终止未完成的读取请求；晚到的请求不能覆盖另一个 App 的状态。懒加载不预取全部应用、原图、声音或过场素材。

从旧 `pl-track`、`pl-vol`、`pl-music` 迁移时做版本化读取与边界校验；不擅自把用户记住的“音乐关闭”改成开启。存储不可用时使用内存并提示收藏不能持久保存，不阻止阅读。

## 8. 导航与过场协议

统一由 NavigationCoordinator 接收“目的地 + 来源”，不再根据当前 URL 猜动画。

| 来源 | 规则 |
| --- | --- |
| 顶部主导航 | Joker，保留用户现有要求 |
| 东京地图地点图标、右侧出发、下方地点列表 | 车站人群；保留现有 `map-travel` 语义 |
| 手机桌面 / App 内部换屏 | 短界面过渡，无全屏主站动画 |
| 手机普通站内链接、展开查看 | 普通站点转场；默认 Joker，不冒充地图旅行 |
| 异世界导航“进入殿堂” | 导航专属认知过渡，见应用设计；不调用车站人群 |
| 浏览器历史、刷新、外链、新窗口操作 | 不额外拦截或重播过场 |

手机的“地图”图标只是打开 `/map`，不会提前播放车站动画；在实际东京地图中选择地点后才使用 `map-travel`。

协调器顺序：校验普通左键导航 → 开始资源准备及遮屏 → 执行路由 → 确认目标内容已提交 → 收起遮罩与恢复焦点。Next.js `router.push()` 不能当作可等待的页面加载 Promise；完成信号来自目标路由提交和内容边界。

每次导航持有唯一令牌；连点不启动第二套动画，后退取消旧任务。沿用现有 15 秒最终看门狗作为迁移基线，超时必须移除遮罩并提供重试或普通导航，不永久黑屏。缺图退回 Joker 或无动画直达；减少动态效果时直接导航。

所有实际链接保留正确 `href`。Ctrl / Cmd 点击、中键、新标签页、复制链接不经过过场；键盘 Enter 与普通点击保持等价。

## 9. 小屏与可访问性

- 320px 宽屏仍能完成阅读、返回、关闭；内容应用不使用整体 `zoom` 或透视来缩小文字。
- 正文字号目标至少 16 CSS px，主要触控热区至少 44 × 44 CSS px。这是项目设计目标，不宣称仅凭此即符合全部无障碍标准。
- 使用 `100dvh`、安全区内边距、正常滚动容器；输入框获得焦点时不被软键盘遮住。
- 模态手机设置 dialog 名称、`aria-modal`、焦点圈定与背景 inert；关闭后回到触发按钮或合适的主内容位置。
- Escape 优先退出当前图片预览，再返回应用层，最后关闭手机；不同时关闭多层。
- 弹层由一个 OverlayManager 管理层级、滚动锁与焦点，不让问卷、预览、手机和转场互相争抢。
- 音效、振动、自动滚动不是完成操作的唯一反馈；默认不请求通知、麦克风或定位权限。
- 减少动态效果关闭非必要旋转、脉冲和全屏认知效果；按钮仍立即反馈。

## 10. 新增应用的最小流程

新增可信功能目录 → 提供共用视图和 canonical 页面 → 声明注册表项 → 按需增加 FastAPI 领域接口 → 添加宿主契约测试。宿主无需判断“如果 App 是某某就怎样”。

首版之后的优先候选：

| 应用 | 实用功能 | 何时值得做 |
| --- | --- | --- |
| 怪盗收件箱 | 联系方式、站点公告、经审核的访客留言 | 有真实交流需求时；不是即时聊天 |
| 双叶工具箱 | 编码、进制、常用算法演示 | 已有可维护工具后，逐个加入 |
| 行动记录 | ACM 训练 / 项目阶段复盘 | 有稳定记录习惯后；私密内容需另做权限 |
| 日程 | 更新日历或公开学习安排 | 不先做复杂日历同步 |

这张表是早期扩展候选。用户新增的追番 / 游戏、手记、友链与角色会话优先级更明确，以 07、08 的分批范围为准；“收件箱不是即时聊天”指真实用户沟通，不排除 INS 内的虚构角色 AI 会话。

不因有扩展机制就批量堆放空 App。

## 11. 验收

1. 新增一个测试 App 只改注册表和自身模块，不改播放器 / 宿主条件分支。
2. 连续打开关闭手机、切换应用、Back / Forward，各 20 次，音频元素和全局监听不累增。
3. 手机详情、刷新直达、展开页面和复制链接指向同一内容。
4. API 失败、动态已撤回、App 加载失败都能返回桌面与关闭手机。
5. 桌面与 390px、320px 小屏、键盘、软键盘、减少动态效果分别检查。
6. 地图三类入口与顶部导航仍使用各自正确过场，应用内部导航不误触发人群。
