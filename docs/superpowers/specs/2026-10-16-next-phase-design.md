# PHANTOM LOG 下一阶段设计总览

日期：2026-10-16（Asia/Shanghai）

状态：设计草案，供评审；不代表已实现或已批准迁移。

适用项目：ScurryCat/Blogs，目前的静态 P5 主题个人博客。

用于分发开发的材料已另整理为 [多 Agent 交接计划](../plans/2026-10-16-agent-handoff/README.md)：包含 11 个任务包、共享文件所有权、依赖、派发提示词与验收模板。源设计继续保留，任务包不代表已实现或已部署。

## 结论

Next.js + React + FastAPI + PostgreSQL + Docker 是合理的目标技术栈，尤其适合把这个项目继续做成个人作品和可扩展的主题应用。不过，收益来自真实的内容管理、应用交互与服务端数据，而不是把静态文件重新包装一遍。

建议形态是：一个 Next.js 前端、一个模块化 FastAPI 后端、一个 PostgreSQL 数据库，通过单机 Docker Compose 部署。暂不采用微服务、Kubernetes、Redis、消息队列或多用户社交体系。React 是 Next.js 的 UI 基础，不是需要额外并行维护的另一套前端。

## 已确认与待评审

已经由用户明确的方向：

- 最终使用 Docker 容器化部署，Next.js / React、FastAPI、PostgreSQL。
- 完善网站内置手机，增加 INS、异世界导航以及后续应用。
- INS 是本站自己的图文动态应用，不接入真实 Instagram。
- 希望扩展追番、日记、游戏、作品集、照片墙和手机友链，合理融入勒布朗、天鹅绒房间、殿堂与印象空间。
- INS 角色对话使用“剧情选项 + AI 自由聊天”；UI 要参考游戏原版。
- 异世界导航需要充分结合游戏设定，不能只按普通搜索工具处理。
- 现有地图关联入口使用车站人群转场，顶部导航仍使用 Joker 过场。

本组草案提出、尚待用户评审的默认方案：

- 首版只允许站主发布；访客无需注册，公开浏览。
- INS 图文基础版不做全站点赞统计、评论、关注或真实用户之间的私信；角色消息按 08 单独交付，收藏只保存在本机。
- 友链推荐独立 COOP 应用并从 INS 提供入口；作品与照片采用“我的殿堂”展厅；技能成长采用天鹅绒房间。具体映射见 07。
- 异世界导航采用“专题殿堂 + 认知关键词 + 印象空间”三种互补入口；不做战斗系统，也不把真实人物标记为“扭曲目标”。
- 手机与独立页面共用应用视图；手机不是阅读内容的唯一入口。
- 首版单服务器、单前端实例、单 API 实例；部署参数需在真实服务器测量后确定。

## 当前项目的出发点

仓库目前没有 Next.js、React、FastAPI 工程或 Docker 配置。本组文档不会暗示这些能力已经存在。

现状依据：

- [phone.css](../../../assets/css/phone.css)：桌面使用图片外壳和透视屏幕，小屏已改为正常流式布局。
- [posts.js](../../../assets/js/posts.js)、[site.js](../../../assets/js/site.js)：文章、站点资料、地图目的地与问卷配置。
- [guestbook-store.js](../../../assets/js/guestbook-store.js)：默认本地留言，可选远端适配器；当前默认不是所有访客共享的留言板。
- [pjax.js](../../../assets/js/pjax.js)、[core.js](../../../assets/js/core.js)：跨页音乐与过场调度。

检查时工作区还有既有问卷样式、脚本和预览测试修改。这些不是本次文档新增内容；迁移基线必须保存“当前工作区效果”，不能只对照远端提交。

## 产品结构

```text
PHANTOM LOG
├─ 主站：文章 / 东京地图 / 关于 / 天气 / 留言
└─ 怪盗手机：随时打开的第二入口
   ├─ INS：图文动态 / 共享相册 / 角色消息
   ├─ 后续日常应用：手记 / 放课后（追番与游戏）/ COOP（友链）
   ├─ 异世界导航：深入专题、寻找内容、探索印象空间
   ├─ 音乐：持久播放服务的控制界面
   ├─ 现有应用：地图 / 天气 / 档案
   └─ 内容场景入口：我的殿堂（作品与照片）/ 天鹅绒房间（技能），按需加入
```

这保留了“白天学生生活、课后怪盗据点”的双层气质：INS 展示日常，异世界导航承载深入探索。具体功能仍使用易懂的中文副标题，让没玩过 P5 的访客也能使用。

## 本阶段不做的事

- 不在这次请求中直接搭脚手架、迁数据库、改线上站点或推送仓库。
- 不把所有旧代码原样塞进 React，再让 PJAX 和 Next Router 同时控制同一页面。
- 不把应用扩展做成可运行任意第三方脚本的插件商店。
- 不把 localStorage 中的旧留言、投票或偏好自动上传，假装它们是服务端真实数据。
- 不把“非商业声明”视为游戏素材、字体、音乐的使用或再分发授权。

## 评审后建议从哪里开始

先完成一个可回退的迁移基线，再建立 Next.js 的持久站点外壳和手机应用宿主。第一个有后端的完整功能选择 INS 的“站主发布一条图文，另一台设备能看到”；之后实现异世界导航专题殿堂。这样每一阶段都有可观察的结果。

本组是设计文档，不是已批准的逐文件实现计划。新增功能按 07 分批选择；角色消息的首个完整版本应同时包含剧情与 AI，不能用一套假聊天界面代替用户确认的混合体验。
