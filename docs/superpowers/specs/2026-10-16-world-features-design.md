# 07 · 日常、羁绊与异世界：功能扩展设计

日期：2026-10-16

状态：产品设计草案；不是已实现功能或整批开发承诺。

入口：[设计总览](2026-10-16-next-phase-design.md)

## 1. 设计主线

把 PHANTOM LOG 做成“可以走进去的个人生活与创作档案”。访客可以像逛普通博客一样直达内容，也可以通过东京地图、手机和场景发现它们。你的信息工程学习、ACM 经历和项目实践是内容主体；游戏设定负责组织体验。

用户明确希望加入追番、日记、游戏、作品集、照片墙、手机友链，以及 INS 内的角色对话；角色对话已选择“剧情选项 + AI 自由聊天”。以下模块分工、名称和分期是建议。

三种组织方式：

| 方式 | 好处 | 代价 |
| --- | --- | --- |
| 全部装进 INS | 手机入口少，能快速做出信息流 | 作品、友链和长日记难以查找，结构化记录被埋没 |
| 每个功能对应一个场景和 App | 游戏元素丰富，各自有展示空间 | 入口迅速膨胀，内容维护重复，容易出现空应用 |
| 场景组织内容，手机提供常用工具，两者读取同一份数据 | 内容有清楚归属，又能交叉发现；推荐 | 要先约定内容来源、入口和返回关系 |

## 2. 世界与功能的对应

| 元素 / 入口 | 本站作用 | 主要内容与操作 |
| --- | --- | --- |
| 勒布朗咖啡馆 | 日常据点 / Now 页 | 近况、最近日记、正在追番 / 玩什么、音乐控制、留言入口 |
| INS | 图文动态与交流 | 动态、相册入口、角色消息；以短内容为主 |
| 手记 App | 日记与日历 | 按日期浏览、心情和自选地点、长短日记、关联照片 |
| 放课后 App | 追番与游戏记录 | 在看 / 在玩、进度、搁置 / 完成、短评和长评链接 |
| COOP App | 友链通讯录 | 真实朋友的网站、介绍、标签、相识故事与明确外链 |
| 我的殿堂 | 作品与记忆展厅 | 作品集、照片墙、真实里程碑；默认二维展示 |
| 异世界殿堂 | 有组织的深度专题 | 项目过程、系列文章、ACM 复盘与知识学习路径 |
| 印象空间 | 零散探索与问题记录 | 分类笔记、小问题、Bug 调查、解题发现、解决后的证据 |
| 天鹅绒房间 | 能力档案与成长关系 | 技能全书、能力对应的作品、“合体”式组合筛选 |

“我的殿堂”与“异世界殿堂”必须在导航上写全：前者副标题为“作品与照片”，后者为“专题与攻略”。P5R 的 My Palace 原本就包含鉴赏、布置与角色交流；这是比把所有展示内容塞进战斗殿堂更贴切的参考。[P5R 官方学生生活介绍](https://p5r.jp/school_life/)

天鹅绒房间的人格面具合体、印象空间与请求的关系，取自原作设定；下面的技能筛选和问题日志是本站改编，不是游戏原有功能。[SEGA P5R 官方介绍](https://asia.sega.com/persona-remaster/p5r/cht/)

## 3. 日常层：勒布朗、手记、放课后

### 勒布朗：每天回来看看发生了什么

保留地图四轩茶屋作为据点的语义，先为现有首页增加勒布朗式的内容组织，不立即重画所有地图地点。建议内容：一句“最近在忙什么”、最近一篇公开日记、正在观看与游玩的各一条记录、最新照片、音乐与留言入口。

柜台上的手记、桌上的手机、墙上的照片可以是装饰性快捷入口；同屏也提供有中文标签的普通链接。手机端使用纵向内容卡片，不要求精确点中场景中的小物件。长文章阅读仍是正常页面。

惣治郎欢迎语可作为可关闭的短篇同人文案，后续与同一套角色会话连接；不会每次访问强制对话，也不自动开启音乐、AI 调用或麦克风。天气展示只读取现有天气服务，不推断访客位置。

### 手记：用存档的视觉记录日常

每条日记像一张存档卡：日期、星期、标题、心情、地点文字、一段摘要；进入后正常阅读正文。日历仅标记真正有公开记录的日期，空白日期不生成“未完成任务”。提供列表与日历两种浏览方式。

内容可以记录一次 ACM 训练的心情、校园生活或一次旅行，但详细题解仍链接到文章。采用 Save/Load 的数字、日期层次和纸片标题语言，不把“查看日记”写成会误导读者的“覆盖存档”。

建议新增日记时默认为草稿且仅自己可见。日记模型将发布状态与可见性分开：`draft/published`、`private/public`；只有已发布且 public 的记录可进入主站、日历、搜索、分享和 AI 上下文。私密日记始终只允许站主在管理端读取，公开界面不显示锁定标题或空白占位。这个能力需要后端权限，不以隐藏链接实现。

### 放课后：追番与游戏放在一个 App

两个页签“追番 / 游戏”，共享封面、状态、短评和筛选交互，保留各自的进度字段。

| 类型 | 重要字段 | 状态 |
| --- | --- | --- |
| 追番 | 作品名、季度 / 季、已看集数、总集数可空、最近观看日期、个人短评 | 想看、在看、看完、搁置、弃坑 |
| 游戏 | 名称、平台、开始 / 完成日期、手填时长可空、个人短评 | 想玩、在玩、通关、搁置、弃坑 |

“通关”不等于全成就；可额外标注真实达成的里程碑。总集数不明时显示“看到第 6 集”，不绘制假的完成率。评分可空，不填不等于零分；剧透评论默认折叠并标注。

首版手动维护，不同步 Steam、Bangumi 或其他账号。状态更新可由站主选择生成一条 INS 动态草稿，确认后发布，避免每次进度 +1 都刷屏。记录页面可关联一篇长评，长评正文仍只有一份。

## 4. 友链：独立 COOP，INS 提供入口

建议独立，而不是只放在 INS 的“关注列表”。友链通常需要稳定的资料、分类和站点跳转，独立通讯录更容易查找；P5 的协助关系也与这个用途相称。[P5R 官方 COOP 介绍](https://p5r.jp/school_life/)

每张卡片包括头像 / 站点标识、站名、介绍、内容标签、可选相识故事，以及“访问网站”。可选阿尔卡那作为站主赋予的视觉主题，不拿它衡量人的价值。不根据点击量生成好感度或 RANK，不虚构朋友的最新动态、在线状态和聊天消息。

INS 个人资料区提供“我的协助者”入口，读取同一份友链数据。角色消息列表明确属于同人体验；真实友链不是可聊天的 NPC，两者不混成一份联系人表。

首版站主管理友链；申请入口可指向已有联系方式或留言流程，未经审核不直接公开。离开本站使用可辨识外链；站点打不开时仍保留卡片，不自动删除朋友。

## 5. 我的殿堂：作品集与照片墙

### 作品展厅

每个作品展示：一句话用途、效果图、个人职责、技术栈、解决的问题、关键取舍、可验证成果、仓库 / 演示链接和当前维护状态。以“这个 P5 博客”作为第一件真实作品；其他课程或竞赛作品等你有材料再录入，不编造奖项。

作品详情提供“查看攻略记录”，进入相应专题殿堂。作品页回答“你做出了什么”，殿堂回答“你怎么做出来”。殿堂仍按现有 `palace_posts` 组织文章；新作品只需可选关联一个殿堂 ID，不把项目数据或照片硬塞进文章关系表。

默认做二维展厅：重点作品、项目卡片、详情。3D 漫游可以是远期实验，不是阅读作品的必经过程。

### 记忆画廊

照片墙支持相册、主题 / 日期筛选、灯箱、说明与拍摄时间可选。照片保持自然比例，外层可以有 P5 拼贴边框，图片本身不强加红色滤镜。照片墙优先展示摄影；游戏截图可进入独立相册，避免混淆。

一张媒体文件可以被相册、INS 和日记共同引用，无需重复上传。照片说明可按使用场景分别填写，但文件与变体只有一套。媒体只要仍被任何公开内容引用就仍然公开；把某一篇日记改为私密不能收回其他公开相册里的同一张照片，管理端必须明确提示。

INS 的“相册”是同一画廊的紧凑视图，不另建一套图库。照片墙与作品展厅在“我的殿堂”里并列，通过标签页分开，避免作品首页被大量生活照淹没。

## 6. 异世界层：殿堂、印象空间、天鹅绒房间

### 殿堂：值得投入时间的专题

延续已有专题设计。“怪盗据点工程”记录博客开发；未来有内容后再开“算法迷宫”和“信号观测站”。章节可以使用入口、探索区、安全屋、秘宝等叙事标签，但旁边始终显示普通标题。

安全屋对应“本节小结 / 下一步”，秘宝对应项目成果、可运行演示或最终总结；不设置必须闯关才能读取的文章。进度若加入，只记录访客主动标记的阅读状态，不把停留几秒视为学会了。

### 印象空间：小问题也有被记录的价值

保留分类探索作为可先上线的版本；进一步增加站主维护的“请求记录”：发现的问题、背景、尝试、结果、关联文章或提交。状态为待探索 / 调查中 / 已解决 / 暂搁置，解决时间与证据由站主填写。

例如“为什么某个动画结束后无法点击页面？”可以形成一条记录，最后链接到真实修复说明；ACM 的一次反例发现也可以是记录，不必为每次发现创建一整座殿堂。

日记侧重“这一天发生什么、我怎么想”；印象空间侧重“哪个问题、如何处理”。同一经历可互相引用。首版没有公开匿名任务提交、自动接单承诺或真正随机生成的迷宫。

### 天鹅绒房间：技能如何成长，如何组合

建议作为个人档案的深层入口，使用蓝黑、冷光和牢门意象。技能全书展示已学习的领域、掌握范围、学习记录以及关联作品，不自封数值等级；例如算法、前端工程、信号处理是否展示，取决于你实际提供的内容。

“合体”是一个可用的组合筛选器：选择两个技能，展示同时使用它们的已发布作品。没有交集时写“还没有对应作品”，可给站主保存一个构想草稿，但不能把模型生成的概念冒充完成的项目。

初期不用 AI 合成技能，不实现面具养成、抽卡或装备系统。能力卡回答“我会什么”，作品展厅提供证据，殿堂解释学习和实现过程。这三层共用技能与作品关系，不复制三套履历。

## 7. 手机入口与跨模块使用

内容齐备后的首屏建议是 INS、手记、放课后、COOP、异世界导航、音乐。现有地图、天气、档案、设置与文章入口仍保留在后续网格，不因设计新功能删除旧入口。功能尚未上线时不展示不可点击的空图标。

我的殿堂可从首页、档案和手机中的展厅入口访问；天鹅绒房间从档案 / 异世界导航的特殊入口进入，不要求每个场景都占一个 App。

建议 canonical 路由（均为未来设计，不表示当前已存在）：

| 模块 | 路由 |
| --- | --- |
| 日记 | `/apps/journal`、`/apps/journal/<id>` |
| 追番 / 游戏 | `/apps/leisure`，筛选类型为 anime / game |
| 友链 | `/apps/coop` |
| 作品 / 照片 | `/showcase`、`/showcase/projects/<slug>`、`/showcase/photos` |
| 技能全书 | `/velvet` |
| INS 与角色消息 | 见 [08 角色消息设计](2026-10-16-character-messaging-design.md) |

一条具体体验：访客在勒布朗看到你完成了博客手机功能 → 打开 INS 动态 → 与双叶进行一段同人对话 → 点“看看这个作品” → 作品详情 → “攻略记录”进入专题 → “使用的技能”进入天鹅绒房间。每次跳转保留明确返回路径，AI 不擅自打开页面。

地图关联出发继续使用人群，顶部导航继续 Joker；手机应用换屏不播放全屏转场。异世界进入使用独立认知过渡，所有入口服从原手机宿主协议。

## 8. 数据边界与增量范围

建议按功能落地时分别扩展，不现在建空表：

| 数据域 | 最小内容 | 复用关系 |
| --- | --- | --- |
| journal_entries | 日期、标题、正文、心情、发布状态、可见性 | media、可选文章关系 |
| leisure_entries | anime / game、名称、状态、分类型进度、短评 | 封面 media、长评 post |
| friend_links | 站名、地址、简介、头像、标签、展示顺序 | INS 与 COOP 读取同一记录 |
| projects | slug、说明、职责、状态、链接、技术标签 | media、可选 palace |
| albums / album_media | 相册、照片关系与顺序、场景说明 | 同一 media 可用于 INS |
| skills / project_skills | 技能说明、证据、项目关系 | 天鹅绒房间与作品详情 |
| exploration_records | 问题、过程、状态、结果、证据链接 | 可选 post / project |

各公开内容域延续 draft / published 与软删除，公开查询由服务端过滤。新数据域的精确字段、外键与 API 需要在各自开发批次合并进 [05](2026-10-16-data-api-design.md)，本节不是现成数据库迁移。

日记私密数据不进入公共搜索、日历计数、SSR 页面、AI 上下文或公用图片缓存；新媒体关系上线时必须同步扩展媒体可见性判断。角色会话是另一数据域，不能当作 moment、友链留言或公开日记。

## 9. 推荐落地顺序

1. 继承 M0 / M1 迁移基线与手机宿主，保持现有站可对照。
2. 完成 M2 图文发布与共享媒体；随后做 COOP 和照片墙，先让手机有真实可浏览的内容。
3. 完成一份真实作品详情与对应专题；补齐放课后和手记，使勒布朗首页有稳定来源。
4. 角色消息先完成一对一界面、双叶 / 摩尔加纳两个角色、每个角色一段完整剧情，并接入同一会话中的 AI 自由输入；不把“只有假聊天 UI”当作混合聊天完成。
5. 内容增长后增加印象空间问题记录、技能全书与合体筛选。大型场景、群聊、3D 展厅、第三方账号同步另行选择。

这些是可调整的产品顺序，不要求一次做完。第一批 UI 可以先校准原版消息界面，以尽早验证你的还原要求；部署上线仍要经过既有 M4 验收。

## 10. 评审与验收重点

- 没玩过 P5 的人能从副标题判断各入口用途，内容可直接分享并在手机外阅读。
- 作品、照片、动态、日记引用同一数据，不因入口不同出现两份正文或两种发布状态。
- 真实友链和虚构角色在文案与数据上清楚分开。
- 私密日记没有标题、图片、计数或 AI 泄漏；改为私密后新请求立即遵守权限。
- 追番 / 游戏不编造实时进度、在线状态、奖杯或平台同步。
- 天鹅绒房间的组合结果都有真实作品证据；空结果不伪造作品。
- 320 / 390px 小屏、桌面、键盘和减少动态效果均可完成核心访问。
