# 04 · 异世界导航：殿堂、认知关键词与印象空间

日期：2026-10-16

状态：待评审草案；用户要求充分结合游戏设定，具体功能方案尚待评审。

入口：[设计总览](2026-10-16-next-phase-design.md)

## 1. 核心主张

东京地图负责“我去哪里”，异世界导航负责“我要深入什么”。同一个博客由此拥有两种入口：日常城市里的地点索引，与进入某个知识 / 项目主题的认知入口。

新加入的作品、照片、技能和问题记录关系见 [07](2026-10-16-world-features-design.md)。作品展厅“我的殿堂”与本文的专题殿堂分别标注；作品可关联专题，专题仍通过 `palace_posts` 引用文章，不把图库、作品资料或技能卡当成文章关系直接存入。

不建议把异世界导航做成另一个地图缩略版，也不建议只做红黑皮肤的搜索框。推荐做成“可以直接用的专题导航 + 可选的关键词仪式 + 印象空间探索”，让游戏设定对应真实内容结构。

## 2. 原作设定与本站改编，分开说明

设定参考以 P5 / P5R 为主，不混用 P5S 的 EMMA / 监狱或 P5X 的不同导航机制。不涉及后期剧情。

| 游戏设定 | 本站改编 | 不能误解成什么 |
| --- | --- | --- |
| 异世界导航指向认知形成的殿堂 | 进入一个主题统一、按阅读路径组织的专题 | 不是普通地图地点，也不是每篇文章都变成一个殿堂 |
| 进入殿堂涉及目标姓名、地点和认知形态等关键词 | 三个有提示的字段定位已发布专题，可保存已发现入口 | 不是密码、权限验证或必须猜中的谜题 |
| 已知殿堂可再次访问 | 已发现入口与最近足迹，一键重访 | 不是永久复制撤回内容的离线存档 |
| 印象空间面向大众，并与请求相关 | 按类别深入零散笔记、发现文章的另一种路径 | 不是将现实访客判断为“扭曲的人” |
| 认知世界的视觉转换 | 短红黑认知过渡，进入专题内容 | 不是车站旅行，也不强制播放长视频 |

官方页面说明了导航与殿堂的关系及印象空间的定位；三关键词和再次访问等操作细节另参考社区资料。表中“本站改编”全部是项目设计，不声称游戏官方存在 INS 或博客学习系统。[SEGA 官方介绍](https://asia.sega.com/persona-remaster/p5r/cht/)、[社区导航条目](https://megamitensei.fandom.com/wiki/Metaverse_Navigator)。

## 3. 三种方案比较

| 方案 | 优点 | 问题 |
| --- | --- | --- |
| 完整模拟原作，必须输入三个准确关键词才可进入 | 仪式感最强 | 新访客不知道暗号；内容难发现；维护别名负担大 |
| 普通搜索工具换 P5 外观 | 快，能立即找到文章 | 与地图和已有搜索重复，缺少导航 App 的独特作用 |
| 已发现殿堂 + 引导关键词 + 印象空间 | 原作结构与实用导航都保留 | 需要认真维护专题，但无需做完整游戏；推荐 |

首版选择第三种。学习目标、待办与“攻略计划”可以以后附加在专题上，不把一个尚未使用的任务管理平台绑进首版。

## 4. 首版三个入口

### A. 已发现殿堂：最快到达

默认落在这个页面，而不是三个空白输入框。公开展示站主已经整理好的专题卡片，包含标题、说明、关键词提示、已发布文章数量和“进入殿堂”。

“已发现”是叙事名称，不代表必须先玩解谜才能解锁。所有公开专题都可从这里进入，搜索引擎和普通文章链接也能到达。

手机中只需选择卡片；独立页提供 `/apps/metanav/palaces/<slug>`。进入后是清晰的专题阅读页：介绍 → 推荐起点 → 有序章节 / 文章 → 相关内容。每个链接旁显示真实标题，不只显示神秘的章节代号。

### B. 认知定位：可选的原作仪式

点击“认知定位”进入三字段流程：

| 界面名称 | 帮助说明 | 数据字段 |
| --- | --- | --- |
| 目标名 | 专题的署名或代号，不是现实攻击目标 | `name` |
| 现实地点 | 内容的来源场景，如个人博客、竞赛训练场 | `location` |
| 认知形态 | 站主为主题设计的意象，如据点、迷宫、工房 | `cognition` |

输入可打字，也可选择公开候选。逐项解释用途；把三字段提示并排压进小屏不可取，应按正常表单纵向排列。

提交后只有三种业务结果：找到一个专题、找到多个需要选择、未找到。后台故障另显示“导航暂时不可用”，不能用“没有反应”掩盖服务错误。

成功后显示匹配的标题和三项认知信息，由用户点“进入殿堂”再执行跳转。**提交关键词不立刻强制离开当前页面。** 多匹配时列出候选，不随机挑一个。

未找到时保留输入并给出已发布专题建议，以及“普通搜索”。不惩罚输错，不显示虚构警戒度或真实人物评价。

### C. 印象空间：开放探索

使用现有文章分类作为“路径”，如 TECH、LIFE、TOOL、GAME、BOOK 等；每条路径旁保留普通中文解释。进入后显示该类公开文章，可继续按标签筛选。

首版复用公开文章列表接口，不另建随机迷宫引擎。可以从当前加载的公开结果中选一条“随便深入”，但不要把随机推荐伪装成 AI 判断。

不按注册、访问天数或等级锁住技术文章。分类没有文章时给出空态；不生成虚构文章来撑满轨道。

基础版不开放读者提交“请求”。下一批可以增加站主维护的问题记录，见 07：待探索 / 调查中 / 已解决 / 暂搁置，并关联真实解决证据；它不等于公开接单平台。以后若需要让读者提出选题建议，再作为经审核的反馈功能设计，不承诺即时回复。

## 5. 一条实际可落地的内容示例

首个专题可从已有博客内容整理，而不是为了 UI 临时捏造履历：

| 项目 | 初始建议 |
| --- | --- |
| 殿堂标题 | 怪盗据点工程 |
| slug | `phantom-base` |
| 目标名 / 地点 / 认知形态 | ScurryCat / 个人博客 / 据点 |
| 目标名别名 | PHANTOM、怪盗手记 |
| 地点别名 | 博客、Blog |
| 认知形态别名 | 基地、Hideout |
| 推荐文章 | `phantom-blog-launch`、`css-p5-menu`、`a11y-checklist`、`assets-and-credits` |

具体顺序在内容评审后确定。以上 slug 来自现有文章；并不意味着所有旧文中的技术描述已经适合新架构，应标注其创作时间和迁移背景。

未来候选可以包括“算法迷宫”（ACM 题解与训练复盘）、“信号观测站”（信息工程笔记）。这些是拟议专题，现有内容不足时保持草稿，不展示假的完成度、奖项或文章数量。

这个映射延续你的真实背景：学习与实践是探索对象，不把“信息工程学生 / ACM 经历”硬编成有罪的殿堂主人。

## 6. 关键词匹配与普通搜索分离

认知定位是确定性匹配，不需要大模型：

1. 字段 trim，执行 Unicode NFKC 规范化和不区分大小写比较；别名按相同规则保存。
2. 三个字段分别命中该专题的标准值或公开别名，再求交集。
3. 只在已发布且有公开文章的专题集合里匹配。
4. 0 个结果为 `not_found`，1 个为 `found`，多个为 `ambiguous`。
5. 不自动把拼音、错别字或任何人名推断成特定人物；需要的同义词由站主明确维护。

普通搜索接受 1–80 个码点的词，搜索公开文章和公开殿堂标题、摘要、标签；首版不检索草稿、图片 EXIF、原始上传名或管理员字段。多个空格分隔词按全部命中处理；中文词组作为子串，不声称已有完善中文分词。

排序建议：标题完全匹配 → 标题 / 别名命中 → 标签命中 → 摘要命中，同档再按时间与 ID 稳定排序。排名规则在 API 中统一，手机和独立页面不能各算一套。

少量内容先使用参数化条件查询；只有测量出查询瓶颈后再增加 `pg_trgm` 索引或专门搜索方案。`pg_trgm` 支持相似匹配和部分文本索引，但不是“装上就拥有中文语义搜索”。[PostgreSQL pg_trgm 文档](https://www.postgresql.org/docs/current/pgtrgm.html)。

## 7. 进入殿堂时的过场

推荐红黑环形 / 认知涟漪的短过渡，目标不超过约 600ms 的视觉编排；这是参考游戏视觉语言的重建，不承诺原视频逐帧一致。先校验目的地，切换内容期间遮屏，目标提交后收起。

- 只在用户明确点击“进入殿堂”时播放，不在打开 App、打字、匹配结果出现时自动触发。
- 不调用东京地图的车站人群，不覆盖顶部导航仍使用 Joker 的规则。
- 缺少可用素材时退回 Joker 或普通导航；不让新美术资源阻塞功能上线。
- 直接访问专题 URL、Back / Forward、打开新窗口不强制重播。
- 系统减少动态效果或用户关闭此类动效时直接进入。
- 不自动启用麦克风，不持续识别对话；首版只做手动文字与选择输入。
- 音效沿用全站开关，默认不制造突然的大音量或不可关闭的低频效果。

具体时间、图形与资源授权是单独视觉验收项；后端不参与动画，也不以假的扫描进度拖慢实际结果。

## 8. 数据与内容维护

殿堂拥有标题、slug、简介、三项标准关键词、字段别名、状态和有序文章关系。文章仍属于博客，不复制一份正文到殿堂表。

同一篇文章可属于多个专题；分类 / 东京地图位置与殿堂关系独立。专题名称不等于现有地图的地点名称，不自动重写 `site.js` 原有地点含义。

只有至少关联一篇公开文章才可发布殿堂。如果关联文章后来全部撤回，公开殿堂列表、详情与匹配自动不再返回该殿堂。管理员仍能看到并修复草稿，不向读者暴露隐藏内容的标题。

站主管理界面先支持新增专题、维护关键词与文章顺序、预览、发布 / 撤回。别名发生重叠时允许返回多候选，但发布预览应提示站主检查，不能悄悄导航到错误专题。

接口细节见 [数据与 API](2026-10-16-data-api-design.md)：

- `GET /nav/palaces`、`GET /nav/palaces/{slug}`。
- `POST /nav/resolve`：只读取与匹配，不产生足迹或写入统计。
- `GET /nav/search`：普通搜索。
- `GET /posts?category=&tag=`：印象空间复用。
- `/admin/nav/palaces`：站主维护。

## 9. 足迹、隐私与安全

最近访问的殿堂 ID 与时间仅保存在本机，上限 30 条，可清除。称为“访问足迹”，不等同于“已读完”。首版不做跨设备同步或阅读等级。

关键词不是密码；所有真实权限由后端执行。所谓“隐藏入口”最多是趣味发现，敏感笔记不能依靠难猜 slug 或关键词隐藏。

默认不保存访客原始搜索词、输入的人名或认知定位内容到分析系统；应用日志只记录接口、耗时、状态和 request ID，不记录请求正文与查询值。普通访问日志也需要对这类参数脱敏。

## 10. 分期与验收

第一期：一个有实际文章的殿堂、公开列表 / 详情、三关键词引导匹配、普通搜索、分类印象空间、本机足迹。动画可先用现有降级效果。

第二期：在真实内容增长后加入更多专题、阅读路径说明、专题预告与自主绘制的认知动效。站主问题记录依照 07 另批实现；公开请求板、学习任务和游戏互动不在基础版顺带实现。

验收场景：

1. 没玩过 P5 的访客也能直接点击专题，在两次操作内到达文章。
2. 三关键词标准值、别名、大小写 / 全角差异均按规则匹配；歧义不会误跳。
3. 未找到、服务不可用、输入不合法是三种不同反馈。
4. 撤回专题或文章后，普通搜索、匹配与足迹重新访问均遵守当前公开状态。
5. 未注册的普通读者无需授权麦克风、定位或通知即可完成全部首版流程。
6. 图标进入、独立页直达、刷新、返回、展开与减少动态效果均有效。
7. 顶部 Joker 与地图人群规则不变，新导航不会污染旧入口。
