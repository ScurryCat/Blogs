# 08 · INS 角色消息：剧情选项与 AI 自由聊天

日期：2026-10-16

状态：用户已确认混合对话方向；具体交互与运行参数为待评审草案。

入口：[设计总览](2026-10-16-next-phase-design.md)、[功能世界设计](2026-10-16-world-features-design.md)

## 1. 核心体验

角色消息属于 INS 内的“消息”页，采用 P5 / P5R 原版 SNS 短信的视觉语言。INS 本身是本站图文应用，不声称原作中存在同款 Instagram 客户端。

同一段会话可以点击预设选项，也可以展开输入框自由聊天。剧情负责稳定的节奏、分支和链接；AI 提供角色化的即时回应。切换方式不是跳进另一个通用聊天网页，也不必重新开一段对话。

全局明确标注“非官方同人互动”；自由生成的消息额外有可辨识的 AI 标记。台词创作不冒充原作对白，AI 不冒充真实站主或实际友链作者。

## 2. 信息结构

```text
INS
├─ 动态：站主发布的图文
├─ 相册：共享画廊的紧凑视图
└─ 消息：游戏角色的同人会话
   ├─ 角色列表
   └─ 单人会话
      ├─ 剧情消息与回复选项
      ├─ 自由输入与 AI 回复
      └─ 返回当前剧情 / 重新开始 / 清除记录
```

个人资料入口放在顶部头像，提供 COOP 快捷入口。真实友链仍在独立应用维护，不混入角色消息列表。角色不显示虚构的实时在线状态。

独立页建议 `/apps/ins/messages` 与 `/apps/ins/messages/<character_id>`；动态详情继续 `/apps/ins/<uuid>`。静态 messages 路由与 UUID 校验明确区分。手机中使用 `phone=ins&screen=conversation&item=<character_id>`，由原宿主管理返回。

URL 只表达角色和界面，不携带会话凭证、原始消息或剧情私有状态。分享角色入口不会分享访问者的聊天记录；聊天记录无公开分享页。

## 3. 混合对话如何切换

进入角色后先给一个短开场与两三个选项，下方提供“自己说一句”。首次展开自由输入时解释：输入与必要会话上下文将发送给 AI 服务；访客主动发送后才调用模型。

```text
剧情节点 → 等待回复
          ├─ 点击选项 → 校验选项 → 固定分支 → 下一个节点
          └─ 自由输入 → 暂存剧情节点 → AI 回复 → 继续自由聊
                                             └─ 回到话题 → 恢复原节点选项
```

关键约定：

- 自由聊天不会把未选择的剧情选项自动判定为已完成。剧情引擎持有 node ID 与版本；模型无权修改。
- 每个可暂停节点都有简短的“回到话题”衔接文案，恢复后不重复插入已经展示过的开场。
- 发送期间输入区给出明确状态，只允许一个在途生成；切换角色后旧回复不能写进新会话。
- AI 服务失败、超时或额度耗尽时保留已输入内容，显示原因，并始终允许继续预设剧情。
- 当前节点版本不匹配时读取最新状态，不重复消费一次选项。重新开始需明确操作，只重置该段剧情，不静默删除聊天。
- 同一角色同时从两处打开时共用会话顺序，过期版本不能覆盖新的分支。

预设选项可以直接展示站内内容卡片。AI 也可以建议打开内容，但服务器只允许输出已验证的公开内容 ID，前端再生成链接，最后由用户点击；AI 不直接导航、发文章、修改日记或改变“好感度”。

## 4. 先做哪些角色

| 角色 | 同人交互主题 | 与站点内容的结合 |
| --- | --- | --- |
| 双叶 | 项目、算法训练、调试过程、游戏 | 作品与技术文章入口；根据实际公开资料介绍博客 |
| 摩尔加纳 | 新访客引导、今天看什么、探索专题 | 已发布内容推荐、回到据点、解释导航用法 |
| 祐介（后续） | 摄影与创作交流 | 用户主动选定的照片 / 作品；初版不声称 AI 看过未传入的图像 |
| 惣治郎（后续） | 勒布朗日常与近况 | 欢迎短剧情、公开日记与音乐入口 |

首批只做前两位的一对一会话；怪盗团群聊留后续。群聊需要发言调度、上下文与多角色一致性，不能把一次请求随意拆成几个头像就宣称还原。

每个角色都有版本化的角色卡：称呼与语气、少量表达示例、可谈话题、默认无重大剧透、站点信息来源和禁止虚构的履历。技术回答仍需诚实，不因扮演双叶就把未经验证的方案说成已在项目执行过。

### 一段同人示例

以下是新写的示例，不是游戏原文，也不代表站点已有对应功能。

双叶：“这个据点还挺像样。你是来逛逛，还是准备拆开看看它怎么运作？”

选项：`看看博客作品` / `聊聊 ACM` / `自己说一句`。

访客自由输入：“算法题卡了一晚上。”

AI 双叶可以用角色语气先问卡在题意、思路还是实现，再给一两条具体建议；不凭空知道用户写了什么代码。下方保留“回到话题”，点击后恢复上述选项。选择“看看博客作品”才出现真实作品卡片，作品尚未发布时用已有公开介绍替代，不能链接到空页面。

## 5. 原版 UI 还原范围

### 区分三种界面

1. **消息页：参考原版 SNS / IM。** 黑白角色头像、SNS 拼贴标识、红黑白主色、消息层次、回复区和确认提示。
2. **场景对话：参考游戏面对面交流。** 角色大立绘、姓名牌、底部对话框；只用于勒布朗等场景的短欢迎语，不套到每条短信上。
3. **INS 动态：本站原创适配。** 原作没有我们设计的图文信息流，不把它宣传为逐像素复刻。沿用字体层次、斜切标题和选择反馈，正文与照片保持可读。

具体消息气泡轮廓、头像比例、左右边距、姓名与正文关系、选择态、出现顺序，要以完整游戏画面校准。素材表只能证明有哪些图形，不能推导整屏尺寸。本次确认了可用素材，尚未完成整屏逐项测量或浏览器对照验证。

### 字体与版式

- 标题、SNS 标识和装饰按钮可用已审核的切片或重新排版；动态中文正文必须是真实文字，不拼成一张不可选择的图片。
- 现有阿里妈妈数黑体可作为粗标题候选，不称为原版字体。聊天正文选择字重适中的清晰黑体；中文、拉丁字符、数字分开校准，避免所有字都加粗描边。
- 斜切和轻微角度用于容器与标题，不将整段聊天内容整体旋转、压扁或透视缩小。
- 桌面可用接近游戏横向构图的展开视图；390px 手机上改为单列，头像和输入区不拥挤。外形允许响应式改编，不强塞 16:9 截图进窄手机壳。
- 实际正文建议不小于 16px，点击区域至少 44px；键盘弹出后仍能看到最后一条消息与输入框，兼容安全区域。
- 单条消息短距离出现即可；不播放地图人群或 Joker 全屏过场。减少动态效果时立即呈现，提示音服从全站开关。
- 气泡中的 AI 标记和错误提示保持可读，不能为了截图相似而隐藏。

开发时先准备同一版本的一对一消息、多人消息和回复选项三种完整参考帧；以一对一为首批实现范围，多人帧仅帮助避免误读样式。分别核对头像、文字层次、边框、留白、选择态、动效顺序，再做手机适配；不以“都是红黑色”判定还原完成。

## 6. 业务边界

建议在 FastAPI 内新增角色消息模块，沿用现有部署，不单独创建聊天微服务。

| 部分 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| React 消息视图 | 消息呈现、输入、选项、滚动与状态 | 角色提示词、密钥、剧情权限判定 |
| 剧情引擎 | 版本化剧本、节点、合法选项、确定性分支 | 让模型猜测或修改完成状态 |
| 会话服务 | 访客隔离、顺序、幂等、保留时间与清除 | 公共动态、真实朋友私信 |
| AI 适配层 | 按角色组织上下文、调用模型、验证输出 | 执行任意工具、直接操作站点数据 |
| 公开内容读取 | 取当前公开且允许推荐的文章 / 作品摘要 | 草稿、私密日记、管理员资料、其他人的会话 |

角色、剧本与界面配置先存版本化仓库文件。会话记录由数据库管理，但不加入公开内容搜索。概念数据为 visitor_sessions、conversations、messages；每条 message 明确 origin 为 user / script / ai / system，并带角色、顺序、时间及生成请求 ID。

模型供应商和模型型号通过服务端配置选择，本次不决定采购或触发付费调用。无需为了两位角色先部署向量库；少量公开内容使用明确查询与受限摘要即可。

## 7. 访客会话、成本与退出

首版无需访客注册。独立匿名会话使用服务端生成的随机凭证和 HttpOnly / Secure / SameSite Cookie，与管理员会话隔离；服务端只保存凭证摘要。知道 conversation UUID 不足以读取会话，每次读取、发送、选项选择、清除都校验归属。状态修改遵守同源与 CSRF 约束。

建议默认保留最近 24 小时会话，到期删除；访客可以立即“清除聊天”。界面说明本站保留规则和第三方模型服务处理，不能承诺第三方也执行相同保留期。会话正文不进入通用日志、分析系统或长期内容备份；如存在短期数据库备份副本，要在隐私说明中准确列明清除周期。

候选运行限制（实现前按真实费用调整）：单次输入最多 1,000 个码点、每次最多 3 个短消息气泡、每访客每天 20 次 AI 请求、每会话 1 个在途请求。服务端同时设 IP 频率、全站并发、输出长度和日预算上限；匿名 Cookie 可重置，不能只依赖它限费。

请求携带客户端生成的幂等 ID，作用域限定到当前访客会话。重试先查询已生成结果，不重复调用模型。额度以原子操作预留，失败释放或按真实上游费用结算；预算计数须能跨 API 重启保存，不以纯内存计数承诺硬预算。首版可用 PostgreSQL 计数，不强制引入 Redis。

关闭面板停止前端接收；后端尽力取消上游请求，已经产生的成本不能假装撤销。返回后可读取已完成结果，不自动重发。达到预算时保留剧本功能并显示“自由聊天今日已暂停”，不冒充角色突然不愿回应。

只允许纯文本 / 受限消息结构与站内内容 ID，不渲染模型任意 HTML、脚本、外链动作。用户输入和检索内容是会话数据，不能覆盖系统角色规则或公开权限。具体防护在实现时写成测试，不只写在提示词中。

## 8. 一个完整的小版本

交付范围：原版风格的一对一消息页、双叶和摩尔加纳、各一段完整预设剧情、同会话 AI 输入、返回剧情、清除记录、失败 / 限额状态、真实公开内容卡片。

暂不加入：自动群聊、语音克隆、语音输入、跨站私信、角色主动推送、跨设备长期记忆、自动评论每条 INS 动态、自动提高好感度。将来可以增加访客主动触发的角色点评，但须明确是同人 / AI 内容，不伪造实际读者互动。

验收条件：

1. 选项分支可重复测试；非法或过期选项不会推进剧情。
2. 在任意允许暂停的节点自由聊天，再返回时保留原来的选择；清除和重开语义明确。
3. 两个浏览器会话不能互读、互写；分享角色 URL 不泄漏记录。
4. AI 失败、停用、限额或断网时，已有剧情仍可读，预设回复不依赖模型。
5. 重复点击、断线重试、前后台切换不重复生成或计费；不能承诺网络异常绝无上游成本，但必须限制并记录重复请求。
6. AI 不暴露草稿 / 私密日记，不编造站主作品，不控制页面自动跳转。
7. 390px、软键盘、桌面展开、键盘操作、减少动态效果和读屏均能完成对话。
8. UI 与指定版本游戏参考帧逐项对照；动态页和自由输入等原创部分明确为适配。

## 9. 与既有文档的关系

本设计扩展 [03 INS](2026-10-16-ins-design.md)，不更改其图文发布数据模型；原“私信不在首版”只指真实用户之间的私信。图文基础版与混合角色消息是两个可独立验收的批次。

精确 API 路径、数据库约束、会话清除任务与模型预算配置在实施本模块时补入 [05 数据与 API](2026-10-16-data-api-design.md)。本次没有接入真实模型、创建密钥或修改现有网站代码。
