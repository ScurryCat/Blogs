# 03 · 本站 INS 图文动态应用

日期：2026-10-16

状态：待评审草案；本站图文动态与“剧情选项 + AI 自由聊天”的角色消息方向已由用户确认。

入口：[设计总览](2026-10-16-next-phase-design.md)

## 1. 产品定位

一个能在怪盗手机中翻看的个人图文手记：校园生活、ACM 训练片段、项目进展、游戏截图、摄影。长文留给博客，短图文放进 INS。

内部应用 ID 为 `ins`，内容类型称 `moment`，避免与博客 `post` 混淆。界面可以保留 INS 作为昵称，独立页标注“ScurryCat 的图文动态”，不使用真实 Instagram 登录、商标图标或接入暗示。

应用完整方向扩展为“动态 / 相册 / 消息”：相册读取共享画廊，消息提供同人角色互动。本文约束图文基础版；角色消息见 [08](2026-10-16-character-messaging-design.md)，其他内容关系见 [07](2026-10-16-world-features-design.md)。游戏短信 UI 是消息页的参考，不声称原作具有本站设计的图文应用。

## 2. 首版边界

图文基础版只由站主发布，访客匿名浏览；角色消息批次额外允许访客发送自己的会话输入，不开放公共发帖。

| 首版包含 | 首版不包含 |
| --- | --- |
| 时间倒序信息流、详情、图片预览 | 注册、关注、推荐算法、真实用户间私信 |
| 1–9 张图片、文字、标签 | 视频、直播、Stories、GIF、任意附件 |
| 个人资料摘要、标签筛选 | 单独维护一套完整社交个人主页 |
| 本机收藏、复制链接 | 服务端点赞计数、公开评论 |
| 站主管理：草稿、预览、发布、撤回 | 访客投稿与内容审核平台 |

点赞若以后加入，必须是真实服务端统计，并设计匿名身份、防刷、限流和删除；首版不显示虚构数字。评论可后续复用统一讨论模块，而不是再建一个与留言板互不相通的系统。

## 3. 核心流程

访客：手机 → INS → 看图文 → 查看详情 / 标签 → 本机收藏或分享 → 返回原滚动位置。也可以直接访问 `/apps/ins` 或 `/apps/ins/<uuid>`。

站主：独立 `/admin` 管理页 → 登录 → 新建草稿 → 上传图片 → 排序、填写替代文本 → 预览 → 发布。手机中的图文部分只做阅读，内容发布留在管理端；这不限制消息页的剧情选项和自由输入。

发布后另一台设备应能看到同一条动态；未发布草稿不应被信息流、搜索、分享页或图片 URL 暴露。

## 4. 页面与视觉

### 信息流

顶部为站主头像 / 名称和简短简介，下面是标签过滤与单列图文卡片。图片是视觉主体，红黑 P5 元素主要用于应用栏、状态和按钮，不给每张日常照片加重度噪点或强行倾斜。

卡片包含图片、页码、正文摘要、标签、发布时间、收藏与分享。默认显示适配过的缩略图，用户主动进入预览才加载更大版本。多图支持左右按钮和手势；不能只有滑动手势一种操作。

列表使用“加载更多”，不以无限滚动作为唯一方式。回到列表恢复筛选、分页结果和滚动位置。

### 动态详情

显示完整文字和图片顺序；文字按纯文本处理，不接受 HTML。URL 分享到 canonical 详情页。链接到相关博客文章可作为后续扩展，首版不把自由输入 URL 当站内路由执行。

### 图片预览

独立前景层，支持上一张 / 下一张、关闭和键盘操作；关闭回到原卡片。手机原有返回规则由宿主统一处理，不新增自己的 body 锁和全局 Escape 监听。

### 必备状态

加载骨架、没有动态、标签无结果、断网 / 请求失败、图片失败、动态撤回、本机存储不可用，分别有可读提示。失败不能显示成空列表；收藏失败不能伪装为已保存。

## 5. 内容与发布规则

- 文字上限 2,000 个 Unicode 码点；可留空，但至少有一张图片。
- 1–9 张图片，单张原始上传不超过 8 MiB；仅接受 JPEG、PNG、WebP。
- 图片顺序从 0 开始，位置唯一；每张图要求 1–200 个码点的替代文本。
- 最多 8 个标签，单标签 1–24 个码点；去除首尾空白、去重，不允许空标签。
- 只有 `draft` 与 `published`；撤回回到 draft，删除为软删除。草稿可暂时没有图片，图片数量和替代文本齐全属于发布门槛。首版没有预约发布、仅朋友可见或密码内容。
- 发布前必须确认所有关联媒体为 `ready`；服务端生成发布时间，不信任客户端时钟。
- 撤回后公开详情和新媒体请求不再返回内容；先前已经被访客下载的图片无法远程收回。
- 编辑使用 `version` 与 `If-Match` 乐观锁；两处编辑发生冲突时返回 412，不默默覆盖较新内容。

摄影地点只保存站主主动填写的文字描述，不采集访客位置。上传时去除 EXIF 等元信息，避免照片携带精确 GPS 或设备信息。

## 6. 图片处理与存储

媒体不进入 PostgreSQL 二进制列；数据库存 ID、对象键、宽高、状态与来源信息，实际文件进入持久媒体卷。

首版流程：鉴权和限额 → 暂存 → 检查真实格式与解码尺寸 → 应用方向 → 去除元信息 → 生成固定尺寸版本 → 原子移动到正式目录 → 标记 ready。任何步骤失败均不可发布。

建议生成最长边 320、640、1280px 的 WebP 版本，不放大小图；原始文件仅站主管理用途。公开视图拿到的是媒体访问接口，不是服务器绝对路径或可绕过权限的原图目录。

草稿图和未关联图不允许匿名读取。即便知道媒体 UUID，也必须根据当前关联内容的公开状态检查访问。详细约定见 [数据与 API](2026-10-16-data-api-design.md)。

图片处理限制像素总量、解码时长与并发；小规模首版使用有界处理并让上传等待完成，不把重要处理丢进无持久保证的后台任务后立刻显示成功。达到实际负载瓶颈后再评估任务队列。

## 7. 接口需求

统一前缀 `/api/v1`，完整契约以 [05](2026-10-16-data-api-design.md) 为准。

| 接口 | 用途 |
| --- | --- |
| `GET /moments?tag=&cursor=&limit=` | 公开图文列表 |
| `GET /moments/{id}` | 公开图文详情 |
| `POST /admin/media` | 站主上传并处理一张图片 |
| `POST /admin/moments` | 新建草稿 |
| `GET /admin/moments`、`GET /admin/moments/{id}` | 管理列表、读取草稿与预览数据 |
| `PATCH /admin/moments/{id}` | 更新内容和完整有序图片列表 |
| `POST /admin/moments/{id}/publish` | 发布 |
| `POST /admin/moments/{id}/unpublish` | 撤回 |
| `DELETE /admin/moments/{id}` | 软删除 |

公开列表按 `published_at DESC, id DESC` 排序，使用不透明游标；默认 12 条，上限 30 条。分页过程中已看过的项目由前端按 ID 去重；撤回后的项目不会因游标而绕过权限过滤。

本机收藏只存 UUID、收藏时间及最小展示摘要，不复制原图、整段正文或草稿。再次打开收藏要重新确认内容仍公开；无效项显示“已不可用”，可由访客移除。界面明确写“仅此浏览器保存”，不承诺跨设备同步。

## 8. 与其他模块的关系

- 头像与简介复用站点资料，不维护第二份相互矛盾的自我介绍。
- 标签复用后端标签表，动态和文章通过各自关联表使用。
- 默认不把每条 INS 动态塞进异世界导航的殿堂；它们分别承载日常与深度内容。
- 手机音乐继续播放，图片预览不自动触发音效或主站过场。
- 公共图文与私密管理通过不同响应模型输出，避免把站主信息、原始文件名或内部路径一并返回。
- 相册与照片墙共用媒体和相册数据；发布在 INS 的同一张图片仍按所有公开引用判断可见性。
- 个人资料提供 COOP 友链入口，不把真实朋友伪装成角色联系人；AI 会话不作为 moment 发布。

## 9. 验收

1. 站主发布图文后，另一浏览器无需登录即可看到；草稿不可见。
2. 手机与独立页展示同一内容、图片顺序和时间；详情可刷新、分享。
3. 上传伪造扩展名、损坏图、超大文件、超像素图会被拒绝，不产生可公开访问的文件。
4. 未登录上传与编辑被拒绝；跨站伪造发布请求被拒绝；旧 version 更新返回 412。
5. 撤回后公开详情、列表与新图片请求不能读到内容。
6. 多页浏览、标签切换和详情返回不丢滚动位置、不重复请求旧游标。
7. 390px 小屏、键盘、图片失败、存储禁用和断网均可返回及关闭。
