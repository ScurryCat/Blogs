# T00 · 基线、工程骨架与集成负责人

开始条件：无。第一阶段串行完成；之后持续承担各包集成，不包办它们的业务实现。

必读：[交接计划](../README.md)、[共享契约](../SHARED-CONTRACTS.md)、[验收](../ACCEPTANCE.md)、[01 架构](../../../specs/2026-10-16-stack-architecture-design.md)、[05 数据 API](../../../specs/2026-10-16-data-api-design.md)、[06 部署](../../../specs/2026-10-16-deployment-roadmap-design.md)。

## 目标与边界

交付一个保留旧站、可启动与可测试的工程基础，使 T01 / T02 能独立开发。不要在本任务中实现完整 INS、AI、导航或生产上线。

初始拥有：`apps/web/package.json` 与配置 / 锁文件、`apps/api/pyproject.toml` 与配置 / 锁文件、`apps/api/app/main.py`、`apps/api/app/router.py`、`apps/api/app/model_registry.py`、`apps/api/migrations/`、`contracts/`、共享测试配置、开发期 `deploy/compose.dev.yaml`。共享骨架文件完成后把 core 交 T01、前端 runtime / phone 交 T02；根注册、迁移与生成类型保留本人所有权。

交付文档：`docs/agent-deliveries/T00-baseline.md`、`T00-result.md`。

## 验收

1. 旧站和问卷可从基线恢复，原始五个文件的非任务修改未丢失。
2. 新 web / api 能在隔离开发环境启动；最小测试真实通过；安装方式可由另一 checkout 重现。
3. T01 / T02 各自拥有明确目录和可编译的共享类型，不需要并行改锁文件 / 根配置。
4. 共享配置与构建不含密钥；没有调用模型或部署生产。
5. 报告分清“基础骨架通过”和“功能尚未实现”。
