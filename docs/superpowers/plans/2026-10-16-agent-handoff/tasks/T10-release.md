## 执行清单

- [ ] 建立明确的本次发布模块清单、镜像 / schema / 配置版本；对未接入模块关闭入口，不能展示坏 App。
- [ ] 生产化 web standalone 和 API 镜像，显式包含 public / static，非 root，锁定依赖，无源码开发挂载、无密钥构建层。
- [ ] Compose 配置 gateway / web / api / db / migrate；只网关对公网，web 不持有 DB 凭据，媒体不作为公开静态目录。迁移只执行一次，成功才启动依赖新 schema 的服务。
- [ ] 检查同源 `/api/v1`、代理前缀、可信代理头、流式响应与健康依赖；不假设 Caddy 自带业务限流或 unhealthy 自动修复。
- [ ] 建立 CI 的旧测试、前端类型 / 单测 / 构建、真实 PostgreSQL API 测试、OpenAPI 漂移、容器构建与冒烟。CI 不自动推送生产部署，除非用户另行授权。
- [ ] 按所选 PostgreSQL 镜像验证卷路径、运行 / 迁移账号、secrets 与权限；不引用不匹配版本的 PGDATA 示例。
- [ ] 实现成对 DB / 媒体备份、校验清单、停止写入窗口与隔离恢复。脚本验证明确目标，不覆盖未知卷，不运行 `down -v`；恢复生产必须另获明确指令。
- [ ] 角色会话上线时，落实短保留数据与长期备份的边界；排除必要的会话正文 / 凭证表数据或准确披露副本保留。恢复后撤销旧会话，核对 AI 预算再启用外部调用。
- [ ] 在隔离环境演练 API / DB 不可用、慢启动、磁盘不足、缺媒体、迁移失败、回退旧镜像与成对恢复；记录真实耗时，RPO 24h / RTO 4h 只是待验证目标。
- [ ] 检查旧 URL 重定向、资源来源与授权、无绝对开发路径、无假内容；游戏素材 / 音乐仍有许可缺口则明确列为发布限制，不删除用户现有资源来掩盖问题。
- [ ] 跑 ACCEPTANCE 的选定模块矩阵，记录 390px / 桌面截图、真实浏览器、跨浏览器与反向代理下效果；输出可发布 / 不可发布的证据清单。

## 验收

1. 隔离环境可从锁定依赖与镜像启动；DB / schema / 媒体不就绪时检查失败，不宣称健康。
2. 实际容器没有公开 DB / API 开发端口，前端构建与镜像层无秘密。
3. 从空隔离环境恢复备份后文章、动态、媒体引用与本次模块核心操作一致，旧会话不可复活。
4. 回退与迁移失败流程不会自动删除新数据或覆盖用户卷。
5. 发布清单的各包已经集成验证；mock 模型、未审素材、未配置域名等限制明确，不把它们写成已上线。

实际命令以 T00 固定的脚本和本包创建的配置为准；记录 `docker compose -f deploy/compose.prod.yaml config`、构建、健康、恢复与 E2E 的真实输出。仅语法检查通过不等于恢复成功。
