# 本次发布的限制与未验证项（T10）

这份文件的作用是**不让人把「没验证」读成「已上线」**（ACCEPTANCE §3）。
左边是事实，右边是原因和「要破除它需要什么」。所有条目都取自各包交付单的未验证清单汇总，
不是新发现，但在这里集中披露一次。**2026-10-19 更新**：站主授权处理 D1 后，本机 Docker Desktop
可用，容器构建/启动/健康联动已补做隔离 Compose 实测（见 `../acceptance/P5-D1-compose-healthcheck-2026-10-19.md`）；

## 5. 树在动：记录时点与「现在」不一致

发布验收做在**一个时间点**上。记录时点前后，别的包还在接入，树一直在变：

| 时刻 | 事实 |
| --- | --- |
| 验收快照时 | `HEAD = 65607e0`，追踪文件里没有 T06 / T08；T08 的文件当时有 TypeScript 错误，**工作区 `next build` 失败** |
| 记录时点（12:57Z） | `HEAD = c4a5bd5`，T05 / T06 / T07 / T08 都已接线；`next build` **已通过**（27 个静态页 + 动态路由），`tsc --noEmit` 退出码 0 |
| **重签时点** | `HEAD = 866e627`，**工作区干净**，T01–T09 全部集成；`alembic head = 528a38f23614`、契约 85 条路径、34 张表；后端整树 **911 passed / 0 failed**、前端 713 通过、旧站 53 零回归 |

所以：**「工作区构建失败」那条已经不再是事实**，但它是验收快照时说清楚过的边界。重签后 T08 也已集成，**唯一仍然成立的 AI 限制是「真实模型未接通」**（见 §3）。
发布时必须重新核对快照与 schema head（`docs/operations/release.md` §1）。

另一个仍然成立的事实：**构建产物包含全部路由**。未列入发布范围的页面（例如 `/apps/journal`）
直接输入 URL 是可达的。如果要求「连直接访问都不可达」，需要在网关加明确的拒绝规则 ——
那是产品决定，本包没有擅自加。
