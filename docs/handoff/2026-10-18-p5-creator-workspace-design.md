# P5 博客 · 第四轮设计草案

## 站主创作台与日常更新体验

日期：2026-10-18  
适用项目：`/Users/学习/blog/Blogs`  
交接对象：后续开发与验收 agent  
实施范围：本轮只执行第一批，第二、三批作为后续路线图。

本文是设计与验收要求，不代表相关功能已经实现或通过测试。接手时应以最新代码和返工交付结果为基线。

## 一、设计目标与实施边界

本轮重点从“访客如何浏览网站”转向“站主如何持续更新网站”。

目标是让站主能够在电脑上整理内容，在真实手机上随手发布图片、记录日记、更新追番和游戏进度，并能安全地跨设备继续编辑。

已确认的方向：

- **日常更新优先**：先做好动态、手记、图片选择和娱乐进度。
- **电脑长文＋手机随手记**：不同设备承担不同任务，共享服务端草稿。
- **独立创作台＋前台快捷入口**：集中管理内容，同时允许从对应页面快速进入编辑。

### 开发阶段

| 阶段 | 建设内容 | 本轮要求 |
|---|---|---|
| 第一批 | 创作台首页、INS 与手记编辑体验、可靠草稿、共享图片选择器、追番与游戏快捷更新 | 必须完成 |
| 第二批 | 桌面文章编辑、Markdown 预览、封面与分类标签、正文插图、文章发布管理 | 仅保留扩展方向 |
| 第三批 | 完整媒体管理、相册批量整理、内容关联、草稿与历史记录检索 | 仅保留扩展方向 |

继续使用 Next.js／React、FastAPI、PostgreSQL。文章、手记、动态保持独立的数据模型，不合并为一种通用内容。

上一轮 UI 仍在返工。接手前必须核对最新代码、未提交修改和交付报告，不得用旧版本覆盖手机宿主、图标、聊天和图库的修改。

本轮不包含生产部署、真实 AI 接入、访客账号体系、完整离线应用或新的游戏化 App。

## 二、产品与界面设计

### 2.1 创作台首页

以 `/admin` 为统一入口，首页围绕四项实际任务组织：

1. **开始记录**：发布动态、写手记、更新追番／游戏进度。
2. **继续编辑**：显示最近工作草稿，包括内容类型、标题或摘要、最近同步时间。
3. **近期内容**：查看最近保存或发布的内容，提供编辑和预览。
4. **内容管理**：连接已有相册、作品、友链等管理页面。

不使用假统计、占位动态或虚构通知填充首页。没有内容时，直接说明可以从哪里开始。

保留现有管理地址和已有业务草稿。编辑旧草稿或已发布内容时，创建或恢复对应工作副本，不要求重新录入。

### 2.2 前台快捷入口

只在确认站主已登录后展示：

| 页面 | 站主操作 |
|---|---|
| INS 列表／详情 | 发布动态／编辑当前动态 |
| 手记列表、日历／正文 | 写手记／编辑当前手记 |
| 放课后 | 快速更新进度、进入完整编辑 |
| 勒布朗生活总览 | 选择发布动态、写手记或更新进度 |

从日历创建手记时，默认使用选中的日期。

快捷入口进入独立编辑页面，不把长表单塞入桌面端的斜屏手机。真实手机浏览器使用全屏、单列编辑布局。

编辑完成或返回时，恢复来源页面、筛选条件和手机 App 上下文。返回地址仅允许站内目标。

前台访客导航继续沿用现有过场规则；创作台内部切换使用轻量反馈，不反复播放全屏过场，也不创建第二个音乐播放器。

隐藏入口不等于授权控制，所有管理接口仍必须验证站主身份。

### 2.3 INS：以选图为起点

推荐操作顺序：

**选择图片 → 输入文字 → 可选收录到相册 → 预览 → 发布。**

具体要求：

- 用户可以直接选择或上传图片，不必先手动创建一条数据库草稿。
- 支持多图选择、排序、移除和逐图替代文本。
- 草稿允许暂时没有图片；正式发布继续遵守现有的 1–9 张可用图片及其他校验规则。
- 相册收录为可选操作，复用已实现的来源关系和联动撤回规则。
- 进入新建相册流程前保护当前草稿；返回后恢复文字、图片顺序和收录选择。
- 不把动态正文自动复制为照片说明。
- 发布前集中说明阻塞原因；失败后保留输入，不显示虚假的成功状态。
- 发布成功后提供“查看动态”和“再发一条”。

沿用现有 JPEG、PNG、WebP 和上传大小限制。对于暂不支持的 HEIC 等格式，明确提示，不承诺自动转换。

### 2.4 手记：先记录，再决定是否公开

编辑主区域保留日期、标题和正文；心情、地点、图片及关联文章放入次要区域。

- 默认日期使用现有站点时区，允许调整。
- 正文延续 Markdown，并提供预览。
- 图片通过共享选择器添加，不再要求输入媒体 ID。
- 新手记默认私密；“保存”不等于“公开”。
- 公开必须是独立、明确的操作，并通过现有发布校验。
- 修改已公开手记时，先保存工作副本；明确更新前，访客继续看到原版本。

访客侧仍使用上一轮确定的存档列表与辅助日历，不在本轮重新设计阅读系统。

### 2.5 放课后：快速更新，完整信息另行编辑

追番快捷更新包含集数、状态和短评；游戏快捷更新包含状态、游玩时长记录和短评。

- 名称、封面等完整信息继续在现有编辑页维护。
- 快捷更新由用户明确确认提交，不采用输入即修改公开记录的方式。
- 提交失败时保留输入，不提前显示更新成功。
- 总集数未知时不生成完成百分比。
- “通关”与“全成就”保持区别，不互相推断。

本轮不增加自动计时、外部账号同步或自动抓取。

### 2.6 视觉原则

创作台延续 P5 的黑白红、剪贴标题、粗边框和选中反色，但正文输入区域保持平直、稳定、清晰。

- 中文正文使用无衬线字体。
- 编辑区不使用影响光标、点击或阅读的倾斜透视。
- 保存反馈可以借用存档语汇，但文案必须明确。
- 自动保存使用安静的状态提示，不持续弹窗或播放音效。
- 手机触控目标实际尺寸至少 44px。
- 软键盘弹出后，光标和关键操作仍可见、可达。
- 数据库 ID、版本号等技术信息不占据主要界面。

## 三、草稿、图片与接口约定

### 3.1 自动保存必须与正式内容隔离

新增管理侧“工作草稿”，第一批只支持 INS 动态与手记。

**禁止把自动保存直接接到现有正式内容更新接口。** 对已发布内容这样操作，可能在用户点击发布前就改变访客看到的内容。

工作草稿至少记录：

- 内容类型、目标内容 ID；新内容的目标 ID 可以为空。
- 所属站主、草稿版本、开始编辑时的正式内容版本。
- 按内容类型校验的编辑数据。
- 图片保留关系、更新时间及草稿状态。

同一站主编辑同一已有内容时，复用一份有效工作草稿；新内容允许存在多份草稿。

工作草稿不是新的公开内容类型，也不能被公开列表、搜索或图库读取。

### 3.2 保存、恢复与跨设备编辑

采用“本机恢复副本＋服务端工作草稿”：

- 停止输入约 1 秒后自动保存；持续输入时最长约 5 秒提交一次。
- 同一草稿的保存请求按顺序处理，旧响应不能覆盖新输入。
- 界面区分“仅保存在本机”“同步中”“已同步”“同步失败”。
- 只有服务端确认后，才能声称可以在另一设备继续编辑。
- 断网保留本机内容；恢复连接后先检查版本，不直接覆盖服务端。
- 发生冲突时暂停自动保存，提供“另存为新草稿”和“放弃本机修改，载入最新版本”。

本机副本按站主身份隔离；未登录时不得展示私密草稿正文。主动退出登录时清除本机恢复副本，不保存认证凭据或 CSRF 信息。

本轮不实现完整离线上传。刷新后无法恢复的待上传文件应提示重新选择；已保存文字和已上传图片关系应能恢复。

### 3.3 明确提交与事务

“发布”“更新正式内容”等操作由后端统一处理：

- 同时检查草稿版本和正式内容版本。
- 复用各内容类型的发布、可见性和图片校验。
- 正式内容、媒体引用、相册收录来源在同一事务内更新。
- 连点提交或网络重试不得生成重复内容、重复收录关系。
- 提交失败保留草稿，正式内容保持原状。

现有服务中若存在内部自行提交事务的逻辑，需要提供可参与外层事务的调用路径，不能通过多个独立提交的请求拼接发布流程。

手记的保存与公开继续分离；自动保存不得改变公开状态。

### 3.4 共享图片选择器

INS 与手记共用同一图片选择器，包含：

- 上传新图片。
- 分页浏览站主已有媒体。
- 查看缩略图、尺寸和上传状态。
- 选择图片，并维护当前内容中的顺序与替代文本。

这里管理的是站主内容媒体，**不是 P5 参考素材库**，两者不合并。

复用图片时引用同一媒体 ID，不重复上传。草稿对媒体的保留关系不能授予匿名访问权限，私密预览继续通过已认证接口。

如果图片已被其他公开内容引用，应提示“该图片已在其他位置公开”。将它用于私密手记，不会使其他公开引用自动失效。

丢弃草稿、移除图片只解除当前关系；本轮不自动删除底层文件。

### 3.5 必要接口与迁移

在现有管理 API 下补齐以下能力：

| 能力 | 行为要求 |
|---|---|
| 创建／恢复工作草稿 | 已有内容重复打开时复用有效草稿 |
| 草稿列表与详情 | 仅站主可读，支持分页和内容类型筛选 |
| 更新工作草稿 | 版本检查，只修改工作副本 |
| 提交工作草稿 | 双版本检查、事务、幂等保护 |
| 丢弃工作草稿 | 不影响正式内容及其他媒体引用 |
| 管理侧媒体列表与详情 | 为共享选择器提供授权范围内的数据 |

复用现有认证、CSRF、错误格式及版本控制机制。公开内容接口保持兼容。

允许增加工作草稿和媒体保留关系所需迁移，但不得丢失旧内容、原公开范围或相册来源关系。同步更新接口说明、前端类型和测试。

## 四、子 agent 分工与接入顺序

| 任务 | 负责内容 | 协作要求 |
|---|---|---|
| C0 集成与契约 | 最新基线、编辑入口、草稿契约、返回上下文 | 先协调正在返工的 UI 文件 |
| C1 草稿后端 | 工作副本、版本冲突、事务提交、幂等、媒体保留及迁移 | 不改变现有公开内容语义 |
| C2 创作台与编辑基础 | 首页、同步状态、本机恢复、跨设备冲突处理 | 提供 INS 与手记共用能力 |
| C3 INS 与图片选择 | 选图上传、排序、相册收录、新建相册返回 | 延续现有图库联动规则 |
| C4 手记与放课后 | 私密／公开编辑流程、图片接入、快捷进度 | 不重做访客阅读和展示页面 |
| C5 验收 | 功能、隐私、迁移、跨设备和回归测试 | 用实际结果区分通过与未验证 |

实施顺序：

1. C0 确认最新基线与接口约定。
2. C1、C2 按共同契约并行开发。
3. 共享编辑能力和图片选择器稳定后，接入 C3、C4。
4. C5 集中验收，修复后提交完整交付说明。

避免多个 agent 同时改写手机宿主、认证层、共享媒体组件或数据库迁移。集成负责人先划分所有权，再并行执行。

## 五、验收标准与交付要求

### 功能与数据

- 访客看不到站主管理入口，直接请求管理接口也无法越权。
- 从前台进入编辑再返回，来源页面、筛选和手机上下文正确恢复。
- INS 多图上传、排序、替代文本与相册收录可用；新建相册往返不丢草稿。
- 手记无需输入媒体 ID；普通保存不会意外公开。
- 编辑公开内容时，自动保存不改变匿名访客视图；明确提交后才更新。
- 跨设备能恢复已同步草稿；版本冲突不会静默覆盖。
- 断网、刷新、登录失效和上传失败均有准确反馈及可验证的恢复行为。
- 重复提交不生成重复内容；提交失败不产生半完成的媒体或相册关系。
- 私密草稿图片不能匿名访问；丢弃草稿不破坏其他内容引用。
- 动态撤回、重发、相册移除和多来源引用规则没有回归。
- 媒体与相册分页正常，选中的对象不因不在当前页就被误判为失效。
- 追番和游戏更新失败时，不显示虚假的成功状态。

### 设备与质量

- 验证桌面键盘操作、320px 和 390px 小屏布局。
- 验证真实触控、软键盘及中文输入法；模拟视口不能代替真机结果。
- 自动保存不得打断输入、吞字、移动光标或破坏输入法组合过程。
- 运行相关前后端测试、类型检查、lint 和构建。
- 在隔离数据库验证迁移、旧数据保留及回退；不得在共享数据库进行破坏性试验。
- 写入型端到端测试使用独立数据，不污染站主真实内容。

### 交付材料

每个任务提交实际修改清单、接口与迁移说明、关键流程截图、测试命令及结果，并单独列出未验证设备和未完成事项。

最终交付必须明确说明：

> 本次完成的是第一批“站主日常创作体验”；文章编辑器和完整媒体管理属于后续阶段，不计入本次完成声明。
